进程简介

程序与进程

  • 程序（Program）：存储在硬盘的静态可执行文件；

  • 进程（Process）：运行中的程序称为进程，可执行文件会被装载到内存中，接着 CPU 会执行程序中的每一条指令。

程序的开始与结束

C 语言程序总是从 main 函数开始执行，main() 函数的原型是：

如果需要向应用程序传参，则选择第二种写法。

那么，究竟是“谁”调用了 main 函数呢？

当你编写并编译一个 C 程序后，编译器会将你的源代码转化为可执行文件。这个可执行文件中有一段入口代码，叫做 启动代码（startup code），链接器会隐式添加启动代码到可执行文件中。启动代码负责一些程序运行前的准备工作。

启动代码中有一个叫 _start 的汇编函数，它是启动代码，也是整个程序真正的入口点。启动代码会初始化静态变量和全局变量，设置堆栈、寄存器等运行时环境，一切都准备好了以后，再去调用 main 函数。

程序结束其实就是进程终止，进程终止的方式通常有多种，大体上分为正常终止和异常终止。

正常终止包括：

  1. 从 main() 函数中返回；
  2. 调用 exit() C 库函数（会做清理工作）；
  3. 调用 _exit() 或者 _Exit 系统调用（直接退出，不进行任何清理工作）。

异常终止包括：

  1. 进程收到用户、系统、程序触发的信号；
  2. 调用 abort() 函数强制终止程序；
  3. 程序运行错误导致崩溃。

进程的内存布局

在 Linux 中，每个进程都有自己独立的虚拟内存空间，由内核映射到物理内存。进程的内存布局通常分为多个段（Segments），其结构如下：

  • Stack（栈）：存储局部变量和程序调用的上下文；
  • 文件映射段：将文件内容直接映射到进程的地址空间，用于动态链接库、共享内存等；
  • Heap（堆）：动态分配的内存；
  • BSS 段：存储未初始化的全局、静态变量；
  • .data（数据段）：存储已初始化的全局、静态变量；
  • .text（代码段）：存储程序代码（机器指令）；
  • 代码段下方还有一段保留区，用于防止空指针访问。

Linux 下的 size 可执行文件 命令可以查看二进制可执行文件的文本段、数据段、bss 段的段大小：

pmap -x <PID> 命令查看指定进程的内存映射。

并行与并发

CPU 在某个时间点只能处理一个任务，但是现代操作系统都支持多任务的。

时间片（Time Slice/Quantum）是操作系统分配给每个可运行任务（进程/线程）的最大连续 CPU 使用时间。当任务的时间片用完时，该进程就会被中断挂起等待下一个时间片，操作系统此时会强制收回 CPU 控制权并进行任务切换。但是，如果进程在时间片结束前进入阻塞或者结束状态，CPU 就会立即进行任务切换。

时间片是操作系统实现"伪并行"的核心机制，它让操作系统中的多个程序从宏观角度来看好像是同时运行的，但这实际上只是并发，而不是并行。

并行与并发的区别：

特性 并行(Parallelism) 并发(Concurrency)
定义 同时执行多个任务 管理多个重叠执行的任务
实现 需要多核/多处理器硬件支持 可在单核上通过时间分片实现
目标 提高计算吞吐量 提高资源利用率
关注点 任务的实际同时执行 任务执行的逻辑正确性
典型场景 科学计算、图形渲染 Web 服务器、操作系统调度

进程的状态

进程状态是操作系统管理进程执行的重要机制，反映了进程在其生命周期中的不同阶段。五态模型：

  • NULL -> 创建状态：一个新进程被创建时的第一个状态；
  • 创建状态 -> 就绪状态：当进程被创建完成并初始化后，一切就绪准备运行时，变为就绪状态，这个过程是很快的；
  • 就绪态 -> 运行状态：处于就绪状态的进程被操作系统的进程调度器选中后，就分配给 CPU 正式运行该进程；
  • 运行状态 -> 结束状态：当进程已经运行完成或出错时，会被操作系统作结束状态处理；
  • 运行状态 -> 就绪状态：处于运行状态的进程在运行过程中，由于分配给它的运行时间片用完，操作系统会把该进程变为就绪态，接着从就绪态选中另外一个进程运行；
  • 运行状态 -> 阻塞状态：当进程请求某个事件且必须等待时，例如请求 I/O 事件；
  • 阻塞状态 -> 就绪状态：当进程要等待的事件完成时，它从阻塞状态变到就绪状态；

进程控制块 PCB

在操作系统中是用进程控制块（process control block，PCB）来描述进程的，每个进程都有一个对应的 PCB，相当于进程的"身份证"。

Linux中的PCB是 task_struct 结构体（定义于 <linux/sched.h>）。

PCB 的主要内容：

组成部分 描述
进程标识信息 进程 ID（PID）、父进程 ID（PPID）、用户 ID（UID）等
CPU 相关信息 寄存器值（PC、SP 等）、程序状态字（PSW）
进程调度信息 进程状态（就绪/运行/阻塞等）、优先级、调度参数
内存管理信息 页表/段表指针、内存分配情况、内存界限寄存器值
文件/资源信息 打开文件列表、分配的 I/O 设备、资源使用情况
进程控制信息 进程间通信（IPC）状态、信号处理表、审计信息

PCB 存储在内核空间内，通常是通过链表的方式进行组织，把具有相同状态的进程链在一起，组成各种队列，比如就绪队列、阻塞队列等。

进程的环境变量

每一个进程都有一组与其相关的环境变量，每个环境变量都以 "name=value"的形式定义。

system() 库函数

system() 函数是标准库中执行 shell 指令的函数，它提供了一种在程序中调用操作系统命令的简单方式。

system() 会执行传入的 shell 命令（command），并返回命令的执行状态。

  2. 在子进程中调用 shell 解释器
  3. shell 解释器执行传入的命令
  4. 等待命令执行完成
  5. 返回执行结果

创建进程： fork()

fork() 是 Unix/Linux 系统中最重要的系统调用之一，用于创建新进程。

Linux 允许使用 fork() 系统调用来一个进程创建另一个进程。

以下是 fork() 系统调用的主要工作内容：

  1. 创建新的进程控制块(PCB)
    • 内核为新进程分配一个唯一的进程 ID(PID)
    • 复制父进程的进程描述符(task_struct)
  2. 复制地址空间
  3. 复制资源
  4. 设置返回值
    • 在父进程中返回子进程的 PID
    • 在子进程中返回 0
    • 如果出错返回-1

fork() 会创建当前进程的副本（子进程），这意味子进程会继承父进程的绝大多数资源，但不是全部。

父子进程相同的资源/信息：

  • 内存空间中用户区的数据相同，包括代码区、全局数据区、堆和栈、环境变量等。注意，父子进程拥有独立的虚拟地址空间，这些变量的值只是初始时一样，之后互不影响。
  • 文件相关的信息，包括文件描述符表、文件偏移量等。
  • 进程属性，包括用户 ID 和组 ID，当前工作目录等。
  • 信号处理方式：信号处理函数设置、信号掩码等。

父子进程中不相同的资源/信息：

  • 进程标识：PID 和 PPID 不同，子进程不会继承父进程的子进程列表。
  • 进程状态：子进程启动之后进入就绪态，运行需要争抢 CPU 时间片而且可能执行不同的业务逻辑。
  • 锁、互斥量等同步原语
  • 进程资源使用统计重置，进程优先级和调度信息可能不同
fork() 的返回值

fork() 执行成功时，会返回两个的值，而父子进程的返回值是不同的：

进程 返回值 意义
父进程 子进程的 PID 标识新创建的子进程
子进程 0 表示这是子进程
错误 -1 只在父进程中返回，表示创建失败

[!important] 为什么 fork() 会有两个不同的返回值？
当调用 fork() 时，内核会创建一个与父进程几乎完全相同的子进程，两个进程的执行上下文完全相同，包括程序计数器(PC)。所以，在父进程的上下文中会返回子进程PID，而在子进程的上下文中返回0。父进程和子进程都会从 fork() 调用处继续往下执行后续的代码。所以，两个不同的返回值，是为了让让父子进程知道自己的身份。

[!NOTE] 最佳实践
对通过 fork() 的返回值来判断当前进程是子进程还是父进程，以便执行不同的逻辑，否则后续代码父子进程都会执行。

执行进程：execve()

exec 族函数是 Unix/Linux 系统中用于替换当前进程映像的一组系统调用，它们会用一个新的程序替换当前进程的代码段、数据段、堆和栈，但保持进程 ID 不变。简单来讲讲，exec 族函数可以在同一个进程中跳转执行另外一个程序。

exec 族中，execve() 是最核心的 程序执行 系统调用，其他 exec 族函数（如 execl(), execvp() 等）最终都会调用它。

参数说明：

  1. pathname：要执行的可执行文件的 完整路径，可以是二进制程序或脚本。
  2. argv：参数数组，形式为 ["程序名", "参数1", "参数2", ..., NULL]，必须以 NULL 结尾。
  3. envp：环境变量数组，形式为 ["VAR1=value1", "VAR2=value2", ..., NULL]，必须以 NULL 结尾。如果为 NULL，则继承当前环境变量。

返回值：这些函数执行成功后不会返回，只有调用失败了，它们才会返回一个 -1，从原程序的调用点接着往下执行。

[!important] execve() 并没有创建新的进程！
与 fork() 不同，execve() 并没有创建新的进程，它只是替换了当前进程。PID、PPID、文件描述符等属性保持不变，而代码段、数据段、堆和栈等用户区数据会被替换成新程序的内容，然后跳转到新程序的 main() 函数处运行。

fork-exec 模型

execve() 和 fork() 常常搭配使用，用来实现创建新的进程并在子进程中运行新的程序。

通常我们会：

  1. 用 fork() 创建一个子进程；
  2. 在子进程中调用 execve()（或其他 exec 家族函数）；
  3. 父进程继续执行或等待子进程完成（通常使用 wait() 或 waitpid()）。

Shell 就是使用了 fork() 和 execve() 来执行用户输入的命令，这是 Unix/Linux 系统设计的核心哲学之一。

监视子进程：waitpid()

waitpid() 是 Unix/Linux 系统中用于等待特定子进程状态变化的系统调用，它是实现进程管理和作业控制的核心函数之一。

参数说明：

pid_t pid：指定要等待的子进程。

  • pid > 0：等待特定子进程（其进程 ID 为 pid）。
  • pid = 0：等待与调用进程同组的任何子进程。
  • pid = -1：等待任何子进程（等同于 wait()）。
  • pid < -1：等待进程组 ID 为 |pid| 的任何子进程。

int *status：用于存储子进程退出状态（可以为 NULL，表示不关心退出状态）。
常用宏解析 status 来获取状态信息：

  • WIFEXITED(status): 检查子进程是否正常退出；WEXITSTATUS(status): 获取退出状态码。
  • WIFSIGNALED(status): 检查子进程是否因信号终止；WTERMSIG(status): 获取终止信号。
  • WIFSTOPPED(status): 检查子进程是否停止（需要 WUNTRACED）；WSTOPSIG(status): 获取导致停止的信号。
  • WIFCONTINUED(status): 检查子进程是否恢复（需要 WCONTINUED）。

int options：控制等待行为（常用选项）。允许你指定是否阻塞等待、关注子进程的哪些状态变化等。

  • 0：默认行为，阻塞模式。直到指定子进程终止，不会报告停止或恢复状态。仅关注终止状态。
  • WNOHANG：非阻塞模式。如果有子进程状态可获取返回该子进程的 PID，如果没有子进程状态可获取返回 0（而不是阻塞）。当你不想让父进程挂起（阻塞），而是希望检查子进程状态并继续其他工作时使用。
  • WUNTRACED：阻塞模式，捕获子进程的终止、停止状态。除了报告终止的子进程，还报告因信号（如 SIGSTOP）而停止（stopped）的子进程状态。用于需要监控子进程暂停状态的程序，例如调试器。
  • WCONTINUED：阻塞模式，捕获子进程的恢复状态。报告因收到 SIGCONT 信号而恢复运行（continued）的子进程状态。用于需要跟踪子进程恢复运行的场景。
  • 这些标志可以通过按位或（|）组合，WUNTRACED 和 WCONTINUED: 仅对特定场景有效，平时很少用。

返回值：

  • > 0：结束的子进程 PID
  • 0：使用 WNOHANG 且没有子进程状态变化
  • -1：出错

结束进程：_exit() 与 exit()

_exit() 是由 POSIX 标准定义的系统调用，用于立即终止一个进程，定义在 unistd.h 中。这个调用确保进程立即退出，不执行任何清理操作（如关闭文件、释放内存、刷新 IO 缓冲区等）。这个函数通常在程序遇到严重错误需要立即退出时使用，或者在某些情况下希望避免清理工作时调用。

  • int status: 父进程可接收到的退出状态码，0 表示成功，非 0 表示各种不同的错误。

[!info] _Exit() 与 _exit() 功能一样，适用于：

  • 子进程退出（避免干扰父进程）。
  • 多线程环境下快速终止（避免死锁）。
  • 调试时强制终止程序。

exit() 是由 C 标准库函数，用于正常终止程序，定义在 stdlib.h 中。在终止进程之前会执行以下操作：

  1. 调用所有通过 atexit() 或 on_exit() 注册的终止处理函数（按注册的逆序执行）。
  2. 刷新所有标准 I/O 缓冲区（如 printf 未输出的内容会被写入文件）。
  3. 关闭所有打开的文件流（FILE*）。
  4. 最终调用 _exit(status) 通知操作系统终止进程。

[!info] exit() 和 _exit() 怎么选？

  • 通常在父进程中使用 exit()，以确保程序在退出前能执行清理操作，如关闭文件和刷新输出。

  • 而对于子进程/多线程，可以使用 _exit() 来确保快速干净地退出，避免干扰父进程或死锁。

练习：实现一个简易 Shell

目标：实现一个简易的 shell，包含以下功能：

  1. 自定义提示符，并显示当前工作目录；
  2. 内置命令包括 cd 和 exit；
  3. 支持后台运行命令；
  4. 支持输入输出重定向和管道符：<, >, >>, 和 |。

下面一步一步来实现上述功能。

  • 在 print_prompt() 函数中，我们使用 cwd() 函数获取当前目录，并打印出自定义的提示符。
  • run_builtin() 处理两个内置命令 cd 和 exit。我们每次执行命令前都要先执行这个函数，检查是否是内置命令。strcmp() 是 C 语言标准库中的一个字符串比较函数，两个字符串相等会返回 0。
  • 现在我们来实现执行单个命令 execute_command() 的函数。为了支持重定向 <, >, >> 以及后台程序执行，除了参数列表 args 以外，我们还需要额外的参数。具体到命令的执行，用到了前面介绍的 fork-exec 模型。不过，在执行之前，要处理输入和输出重定向。在命令执行以后，要根据前台执行还是后台执行来选择是否执行 waitpid()。
  • 为了支持管道符，我们需要一个专门执行带有管道的命令。管道符左右是两个独立的命令，将前一个命令的输出作为后一个命令的输入，所以参数列表需要两个参数列表。pipe() 创建一对文件描述符， pipefd[0] 表示读端，pipefd[1] 表示写端
  • 我们还需要一个 parse_command() 函数来解析用户输入的字符串。参数列表中只有 input 是用户输入，其余的参数都是用来存储解析的结果的。char *strtok(char *str, const char *delim) 是 C 标准库中的一个字符串分割函数，用于将字符串按指定的分隔符拆分成多个标记（token），第一次调用时需要传入字符串，后续调用只需要传入 NULL，就可以继续分割。管道符 | 比较特殊，它的左右是两个命令，所以遇到管道符时需要 return，意味着一个命令解析完毕，在主函数里根据 has_pipe 来判断是否需要继续解析第二个命令。
  • 最后，我们实现主函数，开启一个循环，不断读入命令、解析、执行即可。

进程树、僵尸进程与孤儿进程

在 Linux 中，进程以树形结构组织，每个进程（除 init / systemd）都有一个父进程（Parent Process），并可能创建多个子进程（Child Processes）。

init / systemd 是所有用户进程的祖先（PID=1），由内核负责启动，负责管理系统进程。systemd 是现代 Linux 发行版（如 Ubuntu、CentOS 7+、Fedora）的默认选择，而 init 存在于一些传统或嵌入式系统中。

使用 ps -p 1 可以查看系统中 PID=1 的究竟是 init 还是 systemd。

  • 孤儿进程（Orphan Process）

如果父进程意外结束，但子进程还在运行，此时子进程就称为孤儿进程。在 Linux 中，孤儿进程会自动被 init 进程（PID=1）接管，将其变为自己的子进程。

孤儿进程产生的原因通常是因为父进程被强制终止（kill -9），或者父进程没有正确处理子进程就意外结束。

孤儿进程会被自动接管，通常无需处理。

  • 僵尸进程（Zombie Process）

如果子进程已经结束，但是并没有被父进程回收。此时内核会保留子进程的退出状态和资源占用信息，直到父进程读取。僵尸进程在进程列表（ps）中显示为 <defunct>。

僵尸进程产生的原因是因为父进程未调用 wait() 或 waitpid() 回收子进程，或者父进程忙于其他任务，忽略了子进程的终止信号。

僵尸进程无法通过 kill -9 杀死（因为它已经终止了），虽然不会占用 CPU 或内存，但僵尸进程会占用 PID，PID 耗尽以后将无法创建新进程。

解决方法之一是杀死父进程，init 进程会接收父进程的所有子进程，并自动调用 wait()。

另一种解决方法就是发送 SIGCHLD 信号手动通知父进程：kill -s SIGCHLD <PPID>。

进程关系

进程间存在着多种不同的关系，主要包括：无关系（相互独立）、父子进程关系、进程组以及会话。

  • 无关系：完全独立的两个进程，比如两个不同用户启动的后台服务进程。
  • 父子关系：每个进程都都一个父进程，形成树状结构。init 进程（PID=1）是所有用户进程的根。
  • 进程组：进程组是一个或多个进程的集合，这些进程并不是孤立的，它们彼此之间或者存在父子、兄弟关系，或者在功能上有联系。每个进程必定属于一个、且只能属于一个进程组。每个进程组的组长进程的 ID 就是进程组 ID。
  • 会话（session）：由一个或多个进程组组成。一个会话可以对应一个终端，也可以没有。会话 ID（SID） = 会话首进程的 PID（通常是 Shell）。

守护进程

守护进程（Daemon）是 Linux 系统中一种特殊的后台服务进程，通常在系统启动时运行，独立于终端，长期执行某项任务。Linux 中大多数服务器就是用守护进程实现的，比如 Web 服务器 nginx，SSH 远程登录服务 sshd，MySQL 数据库服务 mysqld。

守护进程与终端无任何关联，用户的登录与注销与守护进程无关、不受其影响，守护进程自成进程组、自成会话，即 pid=gid=sid。

创建守护进程的步骤主要包括：

  1. fork()：创建子进程，父进程退出。使子进程成为孤儿进程，由 init 进程接管。
  2. setsid()：子进程创建新的会话，脱离控制终端，变成守护进程。
  3. chdir("/")：更改工作目录到根目录，避免守护进程运行在可被卸载的文件系统中。可选项。
  4. umask(0)：重置文件权限掩码，确保守护进程创建的文件权限可控。可选项。
  5. 关闭/重定向文件描述符（避免占用终端 I/O）。可选项。
