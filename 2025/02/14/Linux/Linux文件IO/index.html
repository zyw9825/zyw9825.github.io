文件 I/O

文件 I/O 基础

通用 I/O 模型与文件描述符

在 UNIX（以及类 UNIX 系统如 Linux）中，文件、设备（如终端、磁盘、网络套接字等）甚至管道都被抽象为“文件”这一统一的概念。

这种抽象意味着可以使用一组通用的系统调用来操作几乎所有的 I/O 资源，而无需关心底层硬件或资源类型的具体差异。四个与文件相关的核心系统调用是：

  1. open()：打开或创建文件/设备，返回文件描述符。
  2. read()：从文件/设备读取数据。
  3. write()：向文件/设备写入数据。
  4. close()：关闭文件描述符，释放资源。

要实现通用 I/O，就必须确保每一文件系统和设备驱动程序都实现了相同的 I/O 系统调用集。一旦应用程序需要访问文件系统或设备的专有功能时，需要使用特定于设备或文件系统的系统调用或 ioctl() 命令。ioctl() 是对设备或特殊文件执行控制操作的通用接口，允许用户空间程序与驱动程序交互，提供比 read() / write() 更细粒度的控制。

  • 什么是文件描述符？

    文件描述符（File Descriptor, FD） 是 Linux 操作系统中用于管理打开文件的标识符，它是一个非负整数。当进程打开一个文件时，内核会返回一个整数值，这个整数就是文件描述符（FD），供进程在后续操作中使用。每个进程都有一个文件描述符表（File Descriptor Table），存储了当前进程打开的所有文件信息。文件描述符不仅限于普通文件，包括管道、套接字、设备文件等。

  • 默认文件描述符

    在 Linux 中，每个进程启动时都会自动继承三个标准文件描述符，这是系统默认分配的：

文件描述符 名称 作用 默认设备
0 标准输入（stdin） 读取用户输入 键盘
1 标准输出（stdout） 显示正常输出 终端
2 标准错误（stderr） 显示错误信息 终端

  • 文件描述符是有限制的

    在 Linux 操作系统中，一个进程可以打开的文件数是有限制的。对进程来说，文件描述符是一种有限资源。默认情况下，这个最大值是1024，可用 ulimit -n 查看或修改。文件描述符从 0 开始，一直递增，但不会超过最大值（比如 1023）。每一个被打开的文件在同一个进程中都有一个唯一的文件描述符，不会重复，如果文件被关闭后，它对应的文件描述符将会被释放，那么这个文件描述符将可以再次分配给其它打开的文件、与对应的文件绑定起来。

open() 打开文件

在 Linux 中要操作一个文件，首先需要打开该文件，得到文件描述符，然后才能对文件进行后续的读写操作，最后关闭文件。

open() 函数用于打开文件，如果文件不存在，还可以自动创建一个新文件。函数原型如下：

  • pathname：字符串类型，指定要打开或创建的文件路径，可以是相对路径，也可以绝对路径。

  • flags：指定文件的访问模式和其他相关标志。flags 是一个位掩码，可以通过按位或（|）组合多个选项。

    • 访问模式标志（必须指定且互斥，只能选择一个）

      • O_RDONLY：只读模式。
      • O_WRONLY：只写模式。
      • O_RDWR：读写模式。

    • 其它常见标志（可选）：

      • O_CREAT：如果文件不存在，则创建文件（需要指定 mode 参数）。
      • O_EXCL：必须与 O_CREAT 一起使用，不能单独使用，确保文件不存在时才创建，若文件已存在则失败。
      • O_TRUNC：如果文件存在且以写模式打开，清空文件内容。
      • O_APPEND：以追加模式写入，数据追加到文件末尾。
      • O_NONBLOCK：非阻塞模式，适用于特殊文件（如管道、设备文件）。
      • O_SYNC：同步写入，确保数据立即写入底层硬件。
      • O_CLOEXEC：设置文件描述符在 exec 调用时自动关闭。

  • mode：用于指定新文件的权限，只有当 flags 包含 O_CREAT 时才需要提供。这是一个八进制的整数，比如 0755。

    • 这个参数的最大值为：0777，7 = 读 4+ 写 2+ 执行 1，表示所有权限。

    • umask 是一个屏蔽位，用于限制默认权限，通常由 shell 设置，默认为 022，表示屏蔽组用户和其他用户的写权限。可以用过 umask 命令查看并修改：

      mode 参数指定的权限并不是最终的权限，最终权限会受到进程的 umask 值的影响。计算公式为：mode & ~umask。

      比如输入mode是 0666，umask 为 022，~umask为 755，根据公式有 0666 & 0755 = 0644，则最终的权限为 0644，屏蔽掉了组用户和其他用户的写权限。

      在实际应用中，也可以直接使用 Linux 中定义好的宏。这些宏支持使用逻辑或 | 组合。

      宏定义 八进制 权限
      S_IRUSR 0400 用户可读（User Read）
      S_IWUSR 0200 用户可写（User Write）
      S_IXUSR 0100 用户可执行（User Execute）
      S_IRWXU 0700 用户读、写、执行（rwx）
      S_IRGRP 0040 组可读（Group Read）
      S_IWGRP 0020 组可写（Group Write）
      S_IXGRP 0010 组可执行（Group Execute）
      S_IRWXG 0070 组读、写、执行（rwx）
      S_IROTH 0004 其他用户可读（Other Read）
      S_IWOTH 0002 其他用户可写（Other Write）
      S_IXOTH 0001 其他用户可执行（Other Execute）
      S_IRWXO 0007 其他用户读、写、执行（rwx）

  • 返回值：成功将返回文件描述符，文件描述符是一个非负整数；失败将返回-1。

[!IMPORTANT]
open() 是一个系统函数，只能在 linux 系统中使用，windows 不支持。fopen() 是标准 C 库函数，一般都可以跨平台使用。其它系统函数和它对应的标准 C 库函数也是如此。

read() 读取文件

调用 read 函数可从打开的文件中读取数据，其函数原型如下所示：

  • fd：文件描述符。
  • buf：是一个传出参数, 指向一块有效的内存, 用于存储从文件中读出的数据。
  • count：指定需要读取的字节数。
  • 返回值：读取成功返回读取到的字节数。实际读到的字节数可能小于 count 的值，也有可能等于 0（表示文件已经读完）。如果返回 -1 表示读取失败。

write() 写入文件

调用 write 函数可向打开的文件写入数据，其函数原型如下所示：

  • fd：文件描述符。
  • buf：指向一块有效的内存地址, 里边有要写入到磁盘文件中的数据。
  • count：指定写入的字节数。
  • 返回值：如果成功将返回写入的字节数，如果写入出错，则返回-1。如果此数字小于 count 参数，这不是错误，譬如磁盘空间已满，可能会发生这种情况。

close() 关闭文件

close 函数关闭一个已经打开的文件，其函数原型如下所示：

  • fd：要关闭的文件描述符。
  • 返回值：成功关闭返回 0，失败返回 -1。

close 函数会关闭打开的文件描述符，并将其释放回调用进程，供该进程继续使用。显式关闭不再需要的文件描述符是良好的编程习惯。但关闭文件也可能会失败，比如企图关闭一个未打开的文件描述符。所以应该和其他系统调用一样，对 close 进行错误检查。

lseek() 改变文件偏移量

文件偏移量（File Offset）用于指示当前读/写操作的起始位置。每个文件描述符的文件偏移量都是独立的，彼此不受影响。它是内核在管理打开文件时维护的一个指针，记录了下一次读或写操作将从文件的哪个字节开始。

文件刚打开时，偏移量通常从文件开头（0）开始，它会随着读写操作自动更新，也可以通过 lseek() 手动调整。lseek() 函数原型如下所示：

  • fd：文件描述符。
  • offset：偏移量(字节数)。
  • whence：偏移的基准点。可选下列中的一种（宏定义）：
    • SEEK_SET：从文件开头设置偏移量。此时 offset 必须为非负数。
    • SEEK_CUR：从当前位置设置偏移量。此时 offset 可正可负。
    • SEEK_END：从文件末尾设置偏移量。此时 offset 可正可负。
  • 返回值：成功时返回新的当前文件偏移量（相对于文件开头，以字节为单位），失败返回 -1。

通过对 lseek 函数第三个参数 whence 的设置, 经常使用该函数实现如下几个功能，如下所示：

  1. 将文件偏移量移动到文件头部：lseek(fd, 0, SEEK_SET);
  2. 获取当前文件偏移量的位置：lseek(fd, 0, SEEK_CUR);
  3. 获取文件的总大小：lseek(fd, 0, SEEK_END);
  4. 将文件偏移量移动到文件结尾后 1000 个字节：lseek(fd, 1000, SEEK_END);

[!info] 如果程序的文件偏移量已经超过了文件结尾，此时执行 I/O 操作会发生什么呢？

如果你尝试读取(read)超过文件结尾的内容，不会产生错误，read() 会返回 0，表示已经到达文件末尾（EOF）。

如果你尝试在超过文件结尾的位置写入数据，文件会自动扩展，lseek() 设置的偏移量和原本文件末尾之间的空隙会填充 \0（空字节），这段空间被称为文件空洞。然而，文件空洞并不会占用任何磁盘空间，直到后续某个时点，在文件空洞中写入了数据，文件系统才会为之分配磁盘块。空洞的存在意味着一个文件名义上的大小可能要比其占用的磁盘存储总量要大。

一个综合示例

  1. 打开一个已存在的文件 file1。
  2. 创建一个新的文件 file2（如果文件已存在则报错）。
  3. 从 file1 的第 500 字节开始读取最多 1024 字节的数据。
  4. 将读取到的数据写入 file2 的开头。
  5. 处理各种可能的错误，并在完成后清理资源。

总结

  1. 为了对普通文件执行 I/O 操作，首先必须调用 open() 以获得一个文件描述符。随之使用 read() 和 write() 执行文件的 I/O 操作，然后应使用 close() 释放文件描述符及相关资源。这些系统调用可对所有类型的文件执行 I/O 操作。
  2. 所有类型的文件和设备驱动都实现了相同的 I/O 接口，这保证了 I/O 操作的通用性，同时也意味着在无需针对特定文件类型编写代码的情况下，程序通常就能操作所有类型的文件。
  3. 对于已打开的每个文件，内核都维护有一个文件偏移量，这决定了下一次读或写操作的起始位置。读和写操作会隐式修改文件偏移量。使用 lseek() 函数可以显式地将文件偏移量置为文件中或文件结尾后的任一位置。在文件原结尾处之后的某一位置写入数据将导致文件空洞。

深入探究文件 I/O

Linux 系统如何管理文件

  1. 什么是静态文件？

静态文件通常是指存储在磁盘文件系统中的固定内容文件，这些文件的内容不会频繁更改，例如文本文件、图片、PDF 文件等。它们以某种格式保存在磁盘上，用户或程序可以读取或修改这些文件。静态文件的存储和管理依赖于文件系统，而文件系统则建立在磁盘的物理存储结构之上。

  1. 磁盘存储的基本单位

磁盘是静态文件存储的物理载体，其数据存储有明确的层次结构：

  • 扇区（Sector）：磁盘的最小物理存储单位，每个扇区大小为 512 字节（0.5KB）。
  • 块（Block）：多个扇区组成一个块，块是文件系统中用于组织、管理和分配存储空间的基本逻辑单位。块的大小由具体文件系统决定（例如 4KB 或 8KB）。
  • 块设备（Block Device）：操作系统将不同的存储设备（如硬盘）统一抽象为块设备，块是块设备读写的最小单元。

静态文件对应的数据是存储在磁盘设备中不同的块中，操作系统读取硬盘时，一次性读取一个块。那么操作系统是如何知道到底要读取哪一个块呢？

  1. 文件的唯一标识 inode

文件系统在磁盘分区、格式化的时候会将其分为两个区域：

  • 数据区（data blocks）：存储文件的实际内容（数据）。
  • inode 区（inode table）：存储文件的元数据，每个文件对应一个 inode。

在文件系统中，每个文件或目录都有一个唯一的标识——inode（索引节点）。inode 中存储了文件或目录的元数据（metadata），主要包括：

  • 文件类型（普通文件、目录等）
  • 文件大小
  • 权限
  • 时间戳（创建、修改时间等）
  • 数据块指针（指向文件内容所在的块地址）

这个 inode table 就是文件系统维护的索引节点表，通过里面的数据块指针就能找到文件实际存储的地址。inode 和文件内容的关系类似于书里面目录和正文的关系。

可以使用 ls -i 命令查看文件的 inode 编号，每一个 inode 都有唯一的一个 inode 编号。通过 inode 编号

磁盘上存储的 inode 称为 静态 inode，内核通过 struct inode 结构体在内存中维护活跃文件的 inode 信息，称为动态 inode。struct inode 包含了磁盘 inode 的所有元数据和额外扩展字段：如引用计数、缓存状态、锁等。文件首次被打开时，内核从磁盘 inode table 读取元数据，并在内存中创建 struct inode 对象，然后将其加入缓存中，方便后续查找。

  1. 目录与目录项：文件名到 inode 的映射

文件名用于区分不同的文件。需要注意的是，inode 并不存储文件名。inode 和文件名的映射关系是由目录和目录项（dentry）维护的：

  • 目录：目录本身也是一种特殊文件，拥有自己的 inode 编号。目录的内容为目录项列表。
  • 目录项（dentry）：每个目录项记录了一个文件名（或子目录名）及其对应的 inode 编号。目录项不区分文件类型，普通文件或子目录（目录也是文件）都以相同方式记录。

磁盘上的目录项为线性结构，包含文件名和 inode 编号。内核将其转换为内存中的树形结构，包含父子关系、引用计数等，称为目录项缓存（dentry cache）。缓存机制加速了路径解析，避免重复磁盘访问。

[!info] 硬链接与软链接
由于 inode 本身不存储文件名，而是通过目录项建立映射，所以一个 inode 可以被多个目录项引用，这意味着一个文件可以在一个文件系统中以不同的名称出现在不同/不同的目录中，这就是所谓的硬链接（hard link）。在 Linux 中使用 ln source_file target_file 命令就可以创建硬链接。

软链接（symbolic link，或称符号链接）是文件系统中另一种链接类型，与硬链接不同，它不直接指向 inode，而是指向一个文件路径。软链接本质上是一个独立的文件，其内容是一个路径名，操作系统在访问软链接时，会解析这个路径并重定向到目标文件。在 Linux 中使用 ln -s source_file target_file 命令就可以创建硬链接。

  1. 进程对文件的管理

内核通过以下机制来管理进程和它的文件：

  • 进程控制块（Process control block，PCB）：内核使用 task_struct 结构体管理每个进程，PCB 记录进程的所有资源信息。PCB 中有一个 file 指针指向文件描述符表，每个进程都有自己的文件描述符表。
  • 文件描述符表（File Descriptors Table）：文件描述符表是一个数组结构（struct files_struct）。数组中存储着指向文件表（File Table）的指针，数组索引就是文件描述符 fd。
  • 文件表条目（File Table Entry）：文件表条目（内核用数据结构 struct file 表示 ） 用于管理已打开文件的上下文信息，它记录文件的当前读写位置（偏移量）、访问模式（读、写、追加等）、引用计数，以及指向 struct inode 的指针。内核对所有打开的文件维护有一个系统级的描述表格，称为打开文件表（open file description table）。
  • 索引节点（inode）：内存中的 struct inode 包含了文件的所有元数据和额外扩展字段，元数据中有文件内容在磁盘中的实际存储地址。每个文件系统都会为驻留其上的所有文件建立一个 inode 表。

  1. 文件访问流程

当你访问一个文件时，比如 /home/user/file.txt，有以下几个主要步骤：

  1. 路径解析：内核逐级解析路径，通过目录项（dentry）查找 /home/user/file.txt 对应的 inode 编号：
    • 若缓存命中（例如之前访问过该文件），则可以直接获取 file.txt 的 inode 编号（比如 1234）。
    • 若缓存没有命中，则需要到磁盘中逐级查找，并将文件与 inode 编号的映射结果存入到目录项缓存中。
  2. 读取目标文件的 inode 结构体： 获取 inode 编号以后，内核会根据 inode 编号优先从索引节点缓存（inode cache）中查找 inode 结构体：
    • 若缓存命中，直接使用内存中的 struct inode；
    • 若缓存没有命中，从磁盘的索引节点表（inode table）中根据编号找到目标 inode 结构体，创建一个新的 struct inode 对象并加入缓存（inode cache）。
  3. 加载数据块到内存：根据 inode 中的数据块指针，计算文件内容所在的物理磁盘位置。通过块设备驱动，内核将磁盘数据缓存到内存（缓冲区），形成所谓动态文件。后续的读写操作会直接操作内存副本以提升效率。
  4. 关联动态文件与进程：
    5) 创建文件表条目：在打开文件表（open file description table）中创建一个文件表条目（struct file）维护 /home/user/file.txt 文件的动态状态，包括当前读写偏移量、访问模式、引用计数、inode 指针（指向 file.txt 的 struct inode）；
    6) 分配文件描述符 fd：内核会在该进程的文件描述符表中分配一个空闲索引（文件描述符 fd）指向新建的文件表条目。
    7) 返回文件描述符 fd 给用户供后续读写操作。

dup() 和 dup2() 复制 fd

在 Linux 系统下，可以使用 dup 或 dup2 这两个系统调用对文件描述符进行复制。新文件描述符与原文件描述符指向同一个文件表项（即共享文件偏移量等属性）。

  • dup() 系统调用

    • 函数原型：int dup(int oldfd);
    • 功能：dup 会复制一个现有的文件描述符，返回一个新的文件描述符。新文件描述符是当前可用文件描述符表中最小的编号。

  • dup2() 系统调用

    • 函数调用：int dup2(int oldfd, int newfd);

    • 功能：将 oldfd 的引用复制到 newfd，使得 newfd 和 oldfd 共享同一个底层文件描述符。dup2 同样复制一个文件描述符，但允许你指定新文件描述符的编号。

      • 如果 newfd 已打开，会先关闭它，然后将 oldfd 复制到 newfd。

truncate() 和 ftruncate() 是用于 修改文件大小 的系统调用，通常用于 截断文件（缩小）或 扩展文件（填充空字节）。二者的区别主要在于操作的方式（路径 vs 文件描述符）。

  • path / fd：要操作的文件（truncate 用路径，ftruncate 用文件描述符）。

  • length：目标文件大小（字节数，类型以为 off_t）。

    • 如果文件当前长度大于 length，多余部分会被截断（丢弃）。

    • 如果文件当前长度小于 length，文件会被扩展，新增部分填充为零字节（即空洞，sparse file）。

truncate 需要对文件有写权限；ftruncate 需要文件描述符以写入模式打开。

ftruncate 不会改变文件描述符的当前偏移量（可以用 lseek 调整）。truncate 不涉及文件描述符，因此不影响偏移量。

原子操作与竞争冒险

Linux 是一个多任务、多进程操作系统，系统中往往运行着多个不同的进程、任务。原子操作（Atomic Operation）和竞争冒险（Race Condition）是多线程或并发编程中的核心概念。

竞争冒险是指多个线程或进程并发访问共享资源时，由于执行顺序的不确定性而导致程序行为出现错误的情况。

原子操作是解决竞争冒险问题的重要手段之一。原子操作是指在执行过程中不可被中断的操作，即一旦开始执行，它会完整地运行到结束，不会被其他线程或进程打断。

除了原子操作，还有以下方法可以避免竞争冒险：互斥锁 (Mutex)、信号量 (Semaphore)、条件变量 (Condition Variable)等。

[!important] 所有系统调用都是以原子操作方式执行的。

内核保证某系统调用中的所有步骤会作为独立操作而一次性加以执行，期间不会为其他进程或线程所中断。

下面举一个例子来说明原子操作的必要性：

假设有两个独立的进程 A 和进程 B 都对同一个文件进行追加写操作。每一个进程都调用了 open() 函数打开了该文件，但未使用 O_APPEND 标志。此时进程 A 和进程 B 各自得到的文件描述符指向不同的文件表条目，但是文件表条目指向同一个 inode 节点。不同的文件表条目意味着进程 A 和进程 B 有各自独立的偏移量、访问模式等信息，但这并不代表不会发生竞争冒险。考虑下面的场景：

  1. 进程 A 处于运行状态，B 未处于等待运行状态；
  2. 进程 A 调用了 lseek() 函数将偏移量设定到文件末尾（比如 1500 字节处），刚好此时进程 A 的时间片耗尽，然后内核切换到了进程 B；
  3. 进程 B 调用了 lseek() 函数将偏移量设定到文件末尾（也是 1500 字节处），然后调用 write() 函数写入了 100 个字节数据。B 进程时间片耗尽，内核又切换到了进程 A；
  4. 进程 A 恢复运行，当进程 A 调用 write 函数时，从进程 A 的当前位置偏移量（1500 字节处）开始写入 100 个字节。这直接导致进程 B 往文件 A 中写入的数据被覆盖掉。

进程 B 的写入操作导致文件末尾发生了变化，但进程 A 的定位操作和写入操作被分开执行，让进程 A 误以为自己的偏移量就在文件末尾。解决方法就是将定位和写入这两个操作合并为一个原子操作。

使用 O_APPEND 实现原子操作：当 open() 函数的 flags 参数中包含了 O_APPEND 标志，每次执行 write() 写入操作时都会将文件当前写位置偏移量移动到文件末尾，然后再写入数据，这里“移动当前写位置偏移量到文件末尾、写入数据”这两个操作步骤就组成了一个原子操作，加入 O_APPEND 标志后，不管怎么写入数据都会是从文件末尾写，这样就不会导致出现“进程 A 写入的数据覆盖了进程 B 写入的数据”这种情况了。

类似的，同时指定 O_EXCL 与 O_CREAT 作为 open() 函数的标志位时，如果要打开的文件已然存在，则 open() 函数将返回一个错误。对文件是否存在的检查和创建文件就属于同一原子操作。

pread()和 pwrite()

pread() 和 pwrite() 是两个用于文件读写的系统调用，与传统的 read 和 write 相比，它们的主要特点是可以在指定偏移量处读写文件，而不改变文件描述符的当前偏移量。

pread() 和 pwrite() 特别适合多线程或需要随机访问文件的场景。进程下辖的所有线程都共享同一文件描述符表，这也意味着每个已打开文件的文件偏移量为所有线程所共享。当调用 pread()或 pwrite()时，多个线程可同时对同一文件描述符执行 I/O 操作，且不会因其他线程修改文件偏移量而受到影响。

文件所有者与所属组

Linux 是一个多用户操作系统，文件所有者表示该文件究竟属于哪个用户，文件所属组则表示该文件属于哪一个用户组。

文件的所有者通常是创建该文件的用户（除非后续被更改），文件的所属组通常是创建者的主组（Primary Group）。

在 Linux 中，系统并不是通过用户名、用户组名来识别不同的用户、用户组，而是通过用户 ID（UID）、组 ID（GID）。

文件的 UID 和 GID 分别由 struct stat 结构体中的 st_uid 和 st_gid 所指定。

chown() 修改所有者

chown 是一个系统调用，该系统调用可用于改变文件的所有者和所属组。

Linux 系统 shell 中也有一个类似 chown 命令，这个命令内部其实就是调用了 chown 函数来实现功能的。

chown 函数原型如下所示（可以使用 man 2 chown 来查看）：

  • pathname：指定文件路径
  • owner：新的所有者的 uid
  • group：新的所属组的 gid

虽然该函数用法很简单，但是有以下两个限制条件：

1. **更改文件的用户 ID**

   - root（超级用户）进程可以修改文件的用户 ID（`uid`）。
   - **普通用户进程**即使拥有该文件，也无法更改其用户 ID。

2. 更改文件的组 ID

  - **普通用户进程**：可以修改文件的组 ID（`gid`），但必须满足以下条件：
    1. 进程的有效用户 ID（`euid`）必须等于文件的用户 ID（即进程拥有该文件）。
    2. 新的组 ID 必须是进程的附属组 ID 之一（即进程必须属于该组）。
  - **超级用户进程**：可以任意修改文件的组 ID。
文件访问权限

Linux 下的每一个文件都有与之相关联的用户 ID 和组 ID，那么对于一个进程来说亦是如此。以下是和进程相关的用户 ID 和组 ID，有效用户 ID 和有效组 ID 是进程所持有的概念，文件并没有该属性。

ID 类型 作用
实际用户 ID（Real UID, RUID） 标识启动进程的真实用户。
实际组 ID（Real GID, RGID） 标识启动进程的真实用户所属的主组（Primary Group）。
有效用户 ID（Effective UID, EUID） 决定进程访问文件或资源时的权限（用于文件访问权限检查）。
有效组 ID（Effective GID, EGID） 决定进程访问文件或资源时的组权限。
附属组 ID（Supplementary Group IDs） 进程所属的附加组列表（扩展权限，允许访问其他组的文件）。

在 Linux 系统中，当进程尝试对文件进行操作时，操作系统会根据文件的权限位来判断该进程是否有权执行该操作。

进程对文件是否拥有 xx 权限其实质就是指当前执行该进程的用户是否拥有对文件的 xx 权限，但权限检查并不是基于进程的实际用户 ID（Real User ID, RUID）或实际组 ID（Real Group ID, RGID），而是基于有效用户 ID（EUID）和有效组 ID（EGID）。

权限检查的过程：

  1. 检查所有者权限：如果进程的 EUID 与文件的 UID 匹配，则检查文件的“所有者”权限位。
  2. 检查组权限（包括附属组）：如果 EUID 与文件 UID 不匹配，则进入组权限检查。如果进程的 EGID 等于文件的 GID，或者进程的任一附属组 ID 等于文件的 GID，则检查文件的“所属组”权限位。
  3. 检查其它用户权限：如果上述过程都没有匹配成功，则检查文件的“其他用户”权限位。

当然，如果进程的 EUID 是 0（root），直接授予所有权限，无需上面的检查过程。

文件的权限位存储在 struct stat 结构体的 st_mode 字段中。st_mode 字段中除了记录文件的 9 个普通权限之外，还记录了文件的 3 个特殊权限：set-user-ID 位权限、set-group-ID 位权限以及 sticky 位权限，这 3 个特殊权限会动态改变进程的权限上下文：

  • SUID/SGID 对执行文件的影响：
    • 若文件有 SUID 位，进程执行时会临时将 EUID 设为文件所有者。
    • 若文件有 SGID 位，进程执行时会临时将 EGID 设为文件所属组。
  • Sticky Bit 对目录的影响：
    • 仅允许目录中文件的所有者或 root 删除/重命名文件。

[!NOTE] 举个例子
假设有一个文件 data.txt 的权限为 -rw-r-----，所有者 UID=100（用户 A），所属组 GID=200（组 X）。

当前进程的凭证：EUID = 1000（用户 B），EGID = 300（组 Y），附属组 ID = [200, 400]（用户 B 属于组 X 和组 Z）。

虽然 EUID（1000） ≠ 文件 UID（100），EGID（300） ≠ 文件 GID（200），但附属组 ID 中有 200，这与文件的所属组 GID=200 相匹配，那么检查问阿金的组权限 r--，表明用户 B 有读取文件的权限。

目录权限

删除文件、创建文件这些操作也是需要相应权限的。目录（文件夹）在 Linux 系统下也是一种文件，拥有与普通文件相同的权限方案（S/U/G/O），只是这些权限的含义另有所指。

  • 读（r）：对目录而言，这意味着列出目录内容的能力（ls 命令）。
  • 写（w）：允许添加、删除或重命名目录中的条目。
  • 执行（x）：对目录来说，这表示进入目录并访问其中内容的能力。

文件的完整权限检查必须同时考虑文件本身的权限和其所在目录的权限。常见操作的双重权限要求：

操作 所需目录权限 所需文件权限 特殊场景说明
读取文件内容 x（进入目录） r 目录无 x 则无法 stat 文件
修改文件内容 x（进入目录） w 目录无 x 时文件 w 无效
执行文件 x（进入目录） x 脚本需同时有文件 x 和目录 x
删除文件 w + x - 文件权限无关，由目录权限控制
创建新文件 w + x - 文件不存在，仅检查目录权限
重命名/移动文件 源和目标目录均需 w + x - 文件本身权限无关

软链接属于 Linux 系统下的七种文件类型之一，其作用类似于 Windows 下的快捷方式。
