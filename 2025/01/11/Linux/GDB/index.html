GDB

GDB 是一个由 GNU 开源组织发布的、UNIX/LINUX 操作系统下的、基于命令行的、功能强大的程序调试工具。

1. 调试准备

习惯上如果是 c 程序就使用 gcc 编译, 如果是 c++程序就使用 g++编译。如果我们打算对程序进行调试，则必须在程序编译时打开调试选项（-g），还可以额外搭配别的选项，比如：

  • 建议调试时关掉编译器的优化选项（-O0），使用高优化（如 -O2 或 -O3），代码可能被重构，导致调试时行号或变量行为与源代码不一致。
  • -Wall 选项打开所有 warning，也可以发现许多问题，避免一些不必要的 bug。

-g 选项告诉 gcc 在编译时生成调试信息，这些信息会被嵌入到目标文件中（如可执行文件或对象文件），以便调试工具（如 GDB）能够关联源代码与生成的机器码，从而支持源代码级别的调试。所以，带 -g 的目标文件会显著变大。

启动调试程序时，有两个命令可选：

  • run （简写 r）：启动程序并让它运行，直到遇到以下情况之一：
    • 程序正常结束
    • 遇到断点（breakpoint）
    • 发生异常（如段错误）
    • 收到信号（如 Ctrl+C）
  • start（简写 s）：程序启动后立即停在 main 函数的第一行可执行代码处。相当于在 main 函数开头隐式设置一个临时断点（temporary breakpoint），然后运行程序。

可以直接在run命令后面设置参数并运行，语法：run {args}。

如果想让程序 start 之后继续运行，或者在断点处继续运行，可以使用 continue 命令（简写 c）或者 next（简写 n）。

如果调试结束，想要退出gdb，输入 quit（简写 q）。

3. 查看代码

在 GNU Debugger (GDB) 中，list 命令（简写为 l）用于显示源代码。它可以帮助你在调试时查看程序的上下文。

  1. 基本用法
    • 输入 list 或 l：显示当前执行点附近的源代码（默认是 10 行，5 行在当前行之前，5 行之后）。再次按下 l 或者 Enter 会继续显示接下来的代码段。

[!Note]
如果你用 gdb 可执行程序名 启动 GDB，此时还没有开始执行程序，默认的执行点是不确定的。在这种情况下，list 命令通常会显示程序入口点附近的代码（比如 main 函数的开头）。

  1. 指定行号
    • list 行号：显示指定行号附近的代码。
    • list 起始行,结束行：显示从起始行到结束行的代码。例如，list 10,20 显示第 10 行到第 20 行的代码。
  2. 指定函数
    • list 函数名：显示某个函数的源代码。例如，list main 会展示 main 函数附近的代码。
  3. 结合文件
    • list 文件名:行号：显示指定文件中的某一行附近的代码。例如，list main.c:25。
    • list 文件名:函数名：显示指定文件中某个函数的代码。
  4. 调整每次显示的行数
    • set listsize 行数 ：调整每次显示的行数，比如 set listsize 2。可以使用 show listsize 查看当前设置。

另一种查看代码的方式是使用打开 gdb 的 TUI（Text User Interface，文本用户界面）模式，这是 gdb 提供的一种可视化调试方式，允许你在终端更直观的查看源代码、反汇编代码、和寄存器等内容，同时进行调试。非常适合在没有图形化界面的环境中使用。

要进入 TUI 模式并使用其功能，可以通过以下几种命令：

  • layout src：开启显示源代码的 TUI 布局。
  • layout asm：开启显示反汇编代码的 TUI 布局。
  • layout reg：开启显示 CPU 寄存器值的 TUI 布局。
  • layout split：同时显示源代码和反汇编代码的布局。

在TUI模式下，可以结合使用 list 命令来显示你想要查看的文件及其代码。

如果要退出TUI模式，使用快捷键 Ctrl + X, A。

4. 断点操作

断点（breakpoint）是调试的核心功能之一，允许你在程序的特定位置暂停执行，以便检查变量、调用栈等。

在 GDB 中，断点（breakpoint）是调试的核心功能之一，允许你在程序的特定位置暂停执行，以便检查变量、调用栈等。以下是 GDB 中断点操作的详细说明和常用命令：

  1. 设置断点

    • 按行号设置：break 行号 或 b 行号
    • 按函数名设置：break 函数名 或 b 函数名。示例：break main 在 main 函数入口设置断点。
    • 按文件和行号设置：：break 文件名:行号。示例：break main.c:15 在 main.c 文件的第 15 行设置断点。
    • 按文件和函数设置：break 文件名:函数名。示例：break main.c:foo 在 main.c 文件的 foo 函数设置断点。
    • 设置watchpoint（观察点）：watch 表达式：监视指定表达式的值是否改变。观察点（watchpoint）是一种特殊的断点，它允许你在程序中的某个表达式的值发生变化时暂停程序的执行。这对于调试那些由于变量值被意外修改而导致的问题特别有用。

  2. 查看断点

    • 命令：info breakpoints 或 info break，info 可以缩写为 i。
    • 功能：列出所有已设置的断点，包括编号、位置、启用状态等。

    运行 info break 后，GDB 会返回一个表格，包含以下列：
    1. Num：断点编号，用于后续操作（如 delete、disable、commands）。
    2. Type：断点类型，通常是 breakpoint（普通断点），也可能是 watchpoint（观察点）等。
    3. Disp：断点的处置方式。keep：保留断点（默认），del：临时断点，触发一次后删除（由 tbreak 设置）。
    4. Enb：启用状态。y：启用，n：禁用。
    5. Address：断点所在的内存地址（十六进制）。
    6. What：断点的位置信息，通常包括文件名和行号，或函数名。

  3. 删除断点

    • 删除特定断点：delete 断点编号 或 d 断点编号，删除一个或者多个指定断点，或者删除一个连续的断点区间。
      示例：
      • delete 1 删除编号为 1 的断点（编号从 info break 获取）；
      • delete 1 2 3 删除编号为 1、2、3 的断点；
      • delete 4-6 删除断点编号为 4、5、6 的断点。
    • 删除所有断点 delete 或 d。清除所有断点，会提示确认。

  4. 启用/禁用断点

    • 禁用断点：disable 断点编号。示例：disable 2 禁用编号为 2 的断点（断点保留但不生效）。
    • 启用断点：enable 断点编号。enable 2 重新启用编号为 2 的断点。
    • 查看状态：用 info break 检查，Enb 列显示 y（启用）或 n（禁用）。

  5. 条件断点

    • 设置条件断点：break 位置 if 条件。示例：break 10 if x == 5 在第 10 行设置断点，仅当变量 x 等于 5 时暂停。
    • 修改已有断点条件：condition 断点编号 条件。示例：condition 1 x > 0 修改编号 1 的断点条件为 x > 0。
    • 移除条件：condition 断点编号。condition 1 清除编号 1 断点的条件。

  6. 临时断点

    • 命令：tbreak 位置，设置一次性断点，触发一次后自动删除。示例：tbreak main 在 main 函数入口设置临时断点

  7. 实用技巧

    • 保存断点：用 save breakpoints 文件名 保存断点到文件，下次调试用 source 文件名 加载。

    • 自动执行命令：用 commands 断点编号 设置断点触发时自动执行的命令，例如打印变量。

      1. 输入 commands 断点编号。
      2. 在提示符 > 下输入要执行的命令（每行一个）。

5. 调试命令

  1. 断点控制：

    • 继续执行：continue 或 c。功能：从当前断点继续运行，直到下一个断点或程序结束。
    • 单步跳过：next 或 n。功能：在当前断点处执行下一步（不进入函数）。
    • 单步进入：step 或 s。功能：在当前断点处进入函数内部。
    • 跳出函数：finish。功能：从当前函数执行到返回。如果想要跳出函数体必须要保证函数体内不能有有效断点，否则无法跳出。
    • 执行到指定位置：until <line> 功能：持续执行直到执行到某行。

  2. 使用 print 手动打印信息

    • print 变量名或表达式： 显示指定变量或表达式的值。print 可以简写为 p

      每次打印的结果会带一个 $ 编号，可以用它后续引用。

[!NOTE]

如果变量是整数，还可以指定输出格式（默认是十进制）。GDB 中的整数格式化：

  • x：十六进制
  • d：十进制
  • u：无符号十进制
  • o：八进制
  • t：二进制
  • c：字符
  • s：字符串
  • f：浮点数

比如 p/t i 表示以二进制输出 i，p/o i 以八进制输出 i，p/x i 表示以十六进制输出 i。

  • printf "格式字符串", 变量1, 变量2, ... 格式化打印，类似于 C 语言中的格式化输出。

  1. 使用 ptype 查看变量或类型的定义

    • ptype 变量名或类型名 打印变量、类型（结构体、数组、类、指针等）的详细类型信息。

  2. 使用 display 自动打印信息

    • display 变量名或表达式 ：设置变量或表达式在每次程序暂停（如断点或单步）时自动显示。当我们想频繁查看某个变量或表达式的值从而观察它的变化情况时，使用 display 比 print 高效得多。注意，display 没有简写，d 是 delete 的简写。
    • info display：查看已经设置的 display。
    • disable display <编号>：暂时禁用 display，编号从 info display 中查看。
    • undisplay <编号>：删除 display。也可以使用 delete display <编号>。

  3. 使用 info 查看特定信息

    • info sources：显示当前程序的所有源文件。
    • info breakpoints：显示所有已设置的断点及其状态。
    • info stack 或 info s：显示当前调用栈的信息，有助于理解函数调用顺序。
    • info locals：列出当前堆栈帧（即当前执行位置）的所有局部变量及其值。
    • info args：列出当前堆栈帧中函数的参数及其值。
    • info registers：显示 CPU 寄存器的内容。这对于低级别的调试特别有用。
    • info frame 显示关于当前堆栈帧的详细信息。
    • info threads：在多线程程序中，显示所有线程的状态和 ID。
    • info inferiors：查看当前进程和id。使用 inferior {id} 切换进程。
    • info functions [regexp] ：列出可调试的程序中的所有函数。你可以使用正则表达式来过滤特定的函数名。
    • info variables [regexp]：列出可调试的程序中的所有全局变量和静态变量。同样支持使用正则表达式进行筛选。

  4. 使用 x 查看内存信息

    x 命令用于检查内存中的内容。它非常强大，可以以不同的格式和单位显示指定地址处的数据。

    • 语法：x/[数量][格式][单位] 地址

      • 数量：指定要显示的内存单元数量（可选，默认是 1）。
      • 格式：指定显示的格式（例如十六进制 x、十进制 d 等）。
      • 单位：指定每个单元的大小（字节 b、半字 h、字 w、双字 g），默认为字（word，4 个字节）。
      • 地址：要检查的内存地址，可以是具体数值或变量的地址（如 &var1）。

  5. 堆栈和帧管理

    • 堆栈（Stack）：程序运行时用于存储函数调用信息的数据结构。每次函数调用时，会在堆栈上创建一个新的“栈帧”（stack frame），包含函数参数、局部变量和返回地址等信息。

    • 帧（Frame）：堆栈中的一个单元，对应一次函数调用。当前执行的函数对应“当前帧”，其调用者对应“上一帧”，以此类推。

    • backtrace 或 bt：显示当前的调用栈（从当前帧到最外层帧）。

    • bt full：除了函数名和行号，还会显示每个帧中的局部变量值。

    • where 和 bt 功能完全相同。

    • frame 或 f ：显示当前帧的详细信息，包括函数名、源文件名、行号和地址。

    • frame <帧号>（简称 f <帧号>）： 切换到指定编号的帧，可以配合 info locals 查看该帧中的局部变量，配合 info args 查看当前帧的函数参数。

    • up、down：向上移动一帧（从当前帧到调用者帧），向下移动一帧（从当前帧到被调用者帧）。
