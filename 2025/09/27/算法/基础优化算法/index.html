哈希表

哈希表（Hash Table），又称散列表，是一种以键值对（key-value）存储数据的数据结构。

哈希表通过一个哈希函数将键映射到存储数据的数组下标，从而实现高效的数据查找、插入和删除。

哈希表最大的用处就是实现快速查找，因为 key 和数组下标是通过哈希函数建立的映射关系，因此不需要遍历数组就能快速找到想要查找的 key，代价就是需要额外的空间维护哈希表。

哈希表概述

插入与查找

将一个键值对（key-value）存储到哈希表中，主要包括以下步骤：

步骤 1：计算哈希值

  • 使用哈希函数 hash(key) 将键转化为一个整数值。
  • 通过对数组大小取模操作：index = hash(key) % array_size，将哈希值映射到哈希表的数组索引。

步骤 2：检查目标位置

  • 如果目标索引处的桶为空，直接将键值对存储到该位置。
  • 如果目标索引处已有数据（冲突），需要解决冲突。

步骤 3：解决冲突

常见的冲突解决方法：

  1. 开放地址法

    将冲突的元素存储到表中其他未使用的槽位。常见策略包括：

    • 线性探测：从冲突位置开始逐一向后查找空槽。
    • 二次探测：按平方递增的方式查找空槽。
    • 双重哈希：使用第二个哈希函数来计算步长。

  2. 链地址法

    每个数组位置存储一个链表或其他动态数据结构，所有映射到该位置的键值对都存储在链表中。

  3. 再哈希

    使用另一种哈希函数重新计算冲突键的索引。

从哈希表中查找一个键对应的值与插入类似，要经过计算哈希值、检查目标位置、根据冲突解决方法继续查找等步骤。

基本结构

  • 数组：存储值的主要结构，称为哈希表的“桶”或“槽”。
  • 哈希函数：将输入的键转化为数组的索引。
  • 键值对：每个数组元素存储一个或多个键值对。

主要特点

  • 快速查找：平均时间复杂度为 O (1)。
  • 动态扩展：当负载因子（存储元素的数量与表大小的比率）超过阈值时，哈希表会扩容以保持性能。
  • 哈希冲突：多个键映射到同一索引时，需要解决冲突问题。

实现哈希表的编程语言支持

  1. C++: std::unordered_map
  2. Java: HashMap, Hashtable
  3. Python: dict（本质是哈希表）
  4. Go: map 类型
  5. C: 不支持

std::unordered_map

unordered_map 是 C++ 标准模板库（STL）中的一个关联容器，它使用哈希表存储键值对，允许快速的键查找、插入和删除操作。与 std::map 不同，unordered_map 不对元素进行排序，因此其性能更适合对顺序无关的键值操作。

优质数对

问题描述

给你一个长度为 N 的数组 A 和 B，对于满足以下两个条件的数对 (i, j) 被称之为优质数对：

  • 0 <= i < j < N,

  • A[i] = B[j],

  • A[j] = B[i]。

请你输出有多少个优质数对？

题解：

对于 A[i] = B[j] 和 A[j] = B[i]，把索引 i 和 j 换到同侧，有：

  • A[i] = B[j]

  • B[i] = A[j]

于是有： A[i]*SB + B[i] == B[j]*SB + A[j]，当常数 SB 足够大时，能够保证构造唯一的标识符。

[!NOTE]

需要 SB 足够大的原因是为了 保证键值的唯一性，反例：

  • A[i] = 2, B[i] = 11
  • A[j] = 3, B[j] = 7

如果 SB = 10：

  • A[i] * SB + B[i] = 2 × 10 + 11 = 31

  • B[j] * SB + A[j] = 7 × 10 + 3 = 31

两个键值相同，但显然不满足

  • A[i] = B[j]

  • B[i] = A[j]

只有当 SB 足够大时，可以保证 B[i]的倍数和 A[i]的倍数不会相互重叠，从而避免冲突。

  • 时间复杂度：O (n)
    因为每个元素会在哈希表中插入或查询，均摊时间复杂度为常数。
  • 空间复杂度：O (n)
    哈希表存储最多 n 个元素。

贪心算法

贪心（Greedy）算法的原理很容易理解：把整个问题分解成多个步骤，在每个步骤都选取当前步骤的最优方案，直到所有步骤结束；每个步骤都不考虑对后续步骤的影响，在后续步骤中也不再回头改变前面的选择。

贪心算法虽然简单，但它有广泛的应用。例如图论中的最小生成树（Minimal Spanning Tree，MST）算法、单源最短路径算法（Dijkstra）都是贪心算法的典型应用。

贪心算法的主要问题是不一定能得到最优解，因为局部最优并不总是能导致全局最优。

一个问题是否能用贪心算法求解，有时很容易判断，有时不那么容易判断。

如何判断一道题目能否用贪心算法求解？要用贪心算法求解的问题，需要满足以下特征。

（1）最优子结构性质。当一个问题的最优解包含其子问题的最优解时，称此问题具有最优子结构性质，也称此问题满足最优性原理。也就是说，从局部最优能扩展到全局最优。

（2）贪心选择性质。问题的整体最优解可以通过一系列局部最优的选择来得到。

贪心算法没有固定的算法框架，关键是如何选择贪心策略。贪心策略必须具备无后效性，即某个状态以后的过程不会影响以前的状态，只与当前状态有关。

数组 中心下标 是数组的一个下标，其左侧所有元素相加的和等于右侧所有元素相加的和。

如果中心下标位于数组最左端，那么左侧数之和视为 0 ，因为在下标的左侧不存在元素。这一点对于中心下标位于数组最右端同样适用。

如果数组有多个中心下标，应该返回 最靠近左边 的那一个。如果数组不存在中心下标，返回 -1 。

题解：

记数组的全部元素之和为 total，当遍历到第 i 个元素时，设其左侧元素之和为 sum，则其右侧元素之和为 total − nums[i] −sum。左右侧元素相等即为 sum = total − nums[i] − sum，即 2 × sum + nums[i] = total。

当中心索引左侧或右侧没有元素时，即为零个项相加，这在数学上称作「空和」（empty sum）。在程序设计中我们约定「空和是零」。

双指针

双指针又叫尺取法，它是指在区间操作时，用两个指针（游标/下标）同时遍历区间，从而实现高效率操作。

双指针可以把两重循环转化为一重循环，从而把复杂度从 O (n^2) 变成 O (n)。

快慢指针

快慢指针就是两个指针从同一侧开始遍历序列。移动的步长一个快一个慢。移动快的指针被称为“快指针"，移动慢的指针被称为“慢指针"。

典型应用：

  • 判断链表中是否有环：如果快指针和慢指针相遇，链表中存在环。
  • 获取链表中间节点：快指针到达链表末尾时，慢指针指向链表的中间节点（慢指针每次移动一步，快指针每次移动两步）。
  • 删除有序数组重复项：快指针遍历每一个元素，慢指针标记更新后的数组末尾位置。当 nums[fast] != nums[slow] 时，表示找到一个新的非重复元素，此时将 nums[fast] 赋值给 nums[slow + 1]，并移动慢指针。

对撞指针

使用两个指针分别从数组或字符串的两端向中间移动，直到相撞或满足其它特殊条件为止。

典型应用：

  • 两数之和：在已排序数组中寻找目标和。
  • 判断回文串：从两端比较字符，直到中间为止。
  • 字符串反转

分离双指针

分离双指针用于同时处理两个不相交的范围或独立的序列问题。

分离双指针的两个指针，分别属于不同的数组（或链表），两个指针分别在两个数组（或链表）中移动，从而解决相关的算法问题。

典型应用：

  • 合并两个有序数组
  • 归并排序中的合并部分
  • 对两个数组求交集或并集

滑动窗口

滑动窗口（Sliding Window）主要用于处理数组或列表中的子数组或子串问题。

它能够有效地将需要 O (n^2) 时间复杂度的暴力搜索方法优化到 O (n) 的时间复杂度，从而大大提高效率。

滑动窗口算法的核心在于维护一个窗口，这个窗口在数组或者字符串上滑动。窗口的大小可以固定也可以变化。

滑动窗口和双指针中的快慢指针思想类似，通常我们会用两个指针来表示窗口的边界，比如 left 和 right。通过调整这两个指针的位置，我们可以控制窗口的滑动和扩展或收缩。

滑动窗口算法的基本框架：

典型问题：

  • 最大/最小子数组和
  • 最长无重复子字符串
  • 包含某些条件的子数组长度

算法描述：

  1. 初始化游标：i = 0, j = -1 代表一开始是一个空窗口
  2. 控制右游标：固定左游标 i ，当右游标 j 小于 n-1 (n 为数组长度) 的时候，扩大右游标 j 的值，即 j += 1
  3. 控制左游标：根据题目条件进行判定，如果发现条件不满足，则扩大左游标 i 的值，即 i += 1
  4. 记录最优解：在迭代窗口 [i, j] 的过程中，记录最优区间或者满足条件的区间方案数，并且最终返回答案即可

二分查找

二分查找（Binary Search）又称为折半查找，适用于有序顺序表中的元素查找。

它通过不断将查找范围缩小一半来实现查找，时间复杂度为 O (log n)，比线性查找的 O (n) 要高效得多。

二分法是缩小区间，最后定位到一个极小的区间，小到这个区间的左右端点重合，解就是最后这个极小区间的值。所以二分法适用于在一个有序的序列。

二分查找模板

基本步骤

  1. 初始化：设置两个指针，low（表示查找范围的下界）和 high（表示查找范围的上界）。初始时，low 指向数组的第一个元素，high 指向最后一个元素。
  2. 计算中间位置：计算中间元素的位置（向下取整），mid = (low + high) / 2。
  3. 比较元素：
    • 如果 arr[mid] 等于目标值，则查找成功，返回 mid。
    • 如果 arr[mid] 小于目标值，则说明目标值在右半部分，将更新 low ，继续在右半部分查找。
    • 如果 arr[mid] 大于目标值，则说明目标值在左半部分，将更新 high ，继续在左半部分查找。
  4. 结束条件：如果 low 超过 high，则查找失败，返回一个表示未找到的值（如 -1 或 None）。

代码实现

注意事项：

  • 二分查找只适用于有序数组或列表；
  • 在计算 mid 时，要避免溢出，建议使用 mid = low + (high - low) / 2，而不是 mid = (low + high) / 2，特别是在 low 和 high 非常大的情况下；
  • 不要出现 else，把所有情况用 else if 写清楚；

二分查找真正的细节问题，在于到底要给 mid 加一还是减一，while 里到底用 <= 还是 <。

下面介绍几个最常用的二分查找场景：查找目标元素、寻找左侧边界、寻找右侧边界。

二分查找应用

查找目标元素

即标准二分查找，while 里面是 low <= high，当目标元素在 mid 右侧时，更新 low = mid + 1;，当目标元素在 mid 左侧时，更新 high = mid -1;。

[!IMPORTANT]

为什么 while 循环中止的条件是 low <= high？

初始化时，low = 0， high = arr.size () - 1，即闭区间 [0, n - 1]，这个区间其实就是每次进行搜索的区间。

如果找到目标值，即 arr[mid] == target 时即可退出循环，如果没有找到目标值，while 循环应该终止，并返回 -1。

while 循环自然终止的条件应该是：搜索空间为空。

while (low <= high) 的终止条件为 low == high + 1，写成区间的形式就是 [high + 1, high]，此时区间为空。

而如果是 while (low < high)，则终止条件变为 low == high，写成区间就是 [high, high]，此时区间并不为空，还有 arr[high] 这一个元素。如果此时退出循环，就意味着剩余一个元素没有被搜索，可能会得到目标元素不存在的错误结论。

[!IMPORTANT]

为什么是 low = mid + 1， high = mid - 1？而有的代码是 low = mid 或者 high = mid，怎么判断？

这是二分查找的难点之一。

在查找目标元素这个场景中，假设有一个升序数组，我要找目标值的位置。

  • 如果中间元素 mid 的值比目标小，那目标应该在右半部分，这时候应该把 low 调整到 mid+1 的位置。因为 mid 已经比目标小，所以 mid 本身不可能是答案，可以直接跳过。

  • 反之，如果 mid 的值比目标大，那么 high 应该调整到 mid-1，同理。这种情况下，每次都能排除中间的元素，缩小范围，这样就不会重复查 mid 了。这样的话，循环条件一般是 low <= high，这样当 low 超过 high 时结束，避免遗漏。

那什么时候用 low=mid 或者 high=mid 呢？比如在一些变形的二分查找问题中，比如寻找第一个等于目标的元素（左边界），或者最后一个等于目标元素（右边界），这时候可能不需要加一或者减一。

  • 比如在寻找左边界的时候，当 mid 的值等于目标时，可能需要继续在左半部分查找，所以 high=mid 而不是 mid-1，因为可能 mid 就是第一个出现的，或者前面还有相同的元素。这种情况下，如果 high 被设为 mid-1，可能会错过正确的左界。
  • 同样的，在寻找右边界时，当 mid 等于目标时，low 会被设为 mid+1，而 high 可能还是 mid，这样确保不会错过右边界的可能位置。

另外，循环终止的条件也可能不同。比如当使用 low=mid+1 和 high=mid-1 时，循环条件通常是 low <= high，这样可以确保所有元素都检查。而如果使用 low=mid 或者 high=mid 的情况，可能需要调整循环条件为 low < high，否则可能会导致无限循环。例如，当 low 和 high 相邻的时候，mid 等于 low，这时候如果 high=mid，那么 high 不会改变，可能导致死循环。这时候就需要调整循环条件，或者在计算 mid 时采用向上取整而不是向下取整。

总结一下，二分查找的变种很多，基本的原理是根据中间元素与目标的比较来调整搜索范围。更新 low 和 high 时是否需要给 mid +1 或者-1 取决于是否确定中间元素已经被排除，或者是否需要保留中间元素作为可能的候选。

寻找左边界

在有序数组 arr = [1,2,2,2,2,2,3] 中，如果使用二分查找元素 2，那么返回的是索引 3，但如果想要知道 target 的左侧边界（即索引 1），或者右侧边界（即索引 5），需要对算法进行调整。

对于寻找左侧边界，最常见的写法是将 high 初始化为 high = arr.size ()，这意味着约定每次循环的搜索区间都是左闭右开。

[!IMPORTANT]

为什么 while 循环中止的条件是 low < high 而不是 low <= high？

初始化时，low = 0， high = arr.size ()，即左闭右开区间 [0, n)，这个区间其实就是每次进行搜索的区间。

while (low < high) 的终止条件为 low == high，写成区间的形式就是 [high, high)，此时区间为空，可以正确终止。

如果将终止条件改为 while (low <= high)，可能会导致无限循环。举一个最简单的例子，假设有序数组 arr = [8]，算法开始时 low=0，high=1，循环一次后，low=0，high = mid = 0，按照终止条件 while (low <= high)，此后将会无限循环。

[!IMPORTANT]

为什么是 high = mid 和 low = mid + 1？

因为搜索区间是 [low, high) 左闭右开，所以当 arr[mid] 被检测之后，下一步应该去 mid 的左侧或者右侧区间搜索，即 [low, mid) 或 [mid + 1, high)。

[!IMPORTANT]

为什么该算法能够搜索左侧边界？

该算法能正确搜索左侧边界，是因为其通过 缩小搜索区间 和 保留潜在左边界 的策略，确保最终 low 指向第一个大于或等于目标的位置。

核心逻辑：维护左闭右开区间

  • 初始化：high = arr.size ()，搜索区间为 [low, high)（左闭右开）。
  • 循环条件：while (low < high)，当 low == high 时终止循环，确保搜索区间为空时结束。
  • 关键操作：通过比较 arr[mid] 和 target，逐步缩小区间。

(1) 当 arr[mid] >= target，即 mid 可能是左边界，或左边界在 mid 左侧。

  • 操作：将 high 设为 mid，下一轮搜索区间为 [low, mid)。保留潜在解：mid 可能是左边界，但需要继续向左探索更小的索引。

(2) 当 arr[mid] < target，即 mid 及左侧元素均小于 target，左边界必在右侧。

  • 操作：将 low 设为 mid + 1，下一轮搜索区间为 [mid+1, high)。直接排除无效区域：mid 及其左侧元素不可能成为左边界。

终止条件与结果的正确性

  • 终止条件：low == high，此时搜索区间为空。
  • 结果意义：
    • 存在 target：low 指向第一个等于 target 的索引。
    • 不存在 target：low 指向第一个大于 target 的索引（即插入位置）。

[!IMPORTANT]

target 不存在返回索引 low 有什么意义？为什么不和之前一样返回 -1？

在左侧边界查找的代码中，返回的 low 本质上表示的是第一个大于或等于 target 的元素的位置，即使 target 不存在时也是如此。

  1. 当 target 存在时，low 是第一个等于 target 的元素的索引（即左侧边界）；
  2. 当 target 不存在时，low 表示 target 应该插入的位置（保持数组有序），即第一个大于 target 的元素的位置。

算法本身并不直接返回 target 是否存在这个信息，当 target 不存在时，如果想要返回-1，需要额外检查才能确定 target 是否真实存在，注意索引可能越界，需要提前检查：

[!IMPORTANT]

为什么能够寻找右侧边界？

因为当 arr[mid] == target 时，没有立即返回，而是增大「搜索区间」的左边界 low，使得区间不断向右靠拢，达到锁定右侧边界的目的。

[!IMPORTANT]

为什么返回 low - 1？target 不存在时这个返回值有什么意义？

当发现arr[mid] == target时，通过设置low = mid + 1，你实际上是在缩小搜索范围到[mid+1, high)。这样做的目的是继续向右探索，看看是否还有与target相等的其他元素。

因此，最终循环结束时，low会指向比target大的第一个元素的位置，或者超出数组边界的下一个位置。

如果 target 存在，返回low - 1为target的最后一个匹配项，即low之前的一个位置；

如果 target 不存在，返回low - 1则为小于target数的最大索引。
