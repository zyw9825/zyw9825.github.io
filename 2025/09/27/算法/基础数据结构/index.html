环形数组

环形数组（Circular Array）是一种特殊的数据结构，它通过循环使用固定的数组空间来模拟一个环形的队列或缓冲区。

数组只是一块连续的存储空间，不可能有环，我们要做的是在逻辑上把数组变为有环的。

环形数组的关键在于，它维护了两个指针 start 和 end，start 指向第一个有效元素的索引，end 指向最后一个有效元素的下一个位置索引。

这样，当我们在数组头部添加或删除元素时，只需要移动 start 索引，而在数组尾部添加或删除元素时，只需要移动 end 索引。

当 start, end 移动超出数组边界（< 0 或 >= arr. length）时，我们可以通过求模运算 % 让它们转一圈到数组头部或尾部继续工作，这样就实现了环形数组的效果。

哈希表

哈希表（Hash Table），也称为散列表，是一种数据结构，它通过哈希函数将键（key）映射到表中的一个位置来访问记录，以加快查找速度。

哈希表中，不可能出现两个相同的 key，而 value 是可以重复的。

哈希表的底层实现就是一个数组（我们不妨称之为 table）。它先把这个 key 通过一个哈希函数（我们不妨称之为 hash）转化成数组里面的索引，然后增删查改操作和数组基本相同。

理想情况下，哈希函数应该能够均匀地分布键值，以避免冲突（collision）。见的哈希函数包括：

  • 除留余数法：hash (key) = key % table_size
  • 乘法哈希：hash (key) = floor (table_size * (A * key % 1))，其中 A 是常数（通常取 (sqrt (5) - 1) / 2）
  • 字符串哈希：对于字符串类型的键，可以通过将字符的 ASCII 码进行某种运算得到哈希值

哈希冲突是一定会出现的，因为这个 hash 函数相当于是把一个无穷大的空间映射到了一个有限的索引空间，所以必然会有不同的 key 映射到同一个索引上。

出现哈希冲突的情况怎么解决？两种常见的解决方法，一种是拉链法，另一种是线性探查法（也经常被叫做开放寻址法）。

说白了就是纵向延伸和横向延伸两种思路：

拉链法相当于是哈希表的底层数组并不直接存储 value 类型，而是存储一个链表，当有多个不同的 key 映射到了同一个索引上，这些 key -> value 对儿就存储在这个链表中，这样就能解决哈希冲突的问题。

而线性探查法的思路是，一个 key 发现算出来的 index 值已经被别的 key 占了，那么它就去 index + 1 的位置看看，如果还是被占了，就继续往后找，直到找到一个空的位置为止。常见的线性探查法法包括线性探测、二次探测和双重哈希。

  • 线性探测：probe (i) = (hash (key) + i) % table_size
  • 二次探测：probe (i) = (hash (key) + i^2) % table_size
  • 双重哈希：使用第二个哈希函数来计算步长，probe (i) = (hash1 (key) + i * hash2 (key)) % table_size

负载因子（Load Factor）是指哈希表中已存储元素的数量与哈希表容量的比值。负载因子过高会导致更多的哈希冲突，从而降低查找效率。通常需要在负载因子达到某个阈值时进行扩容（rehashing）。

  1. 不能依赖哈希表的遍历顺序。

    由于 hash 函数要把 key 进行映射，所以 key 在底层 table 数组中的分布是随机的，不像数组/链表结构那样有个明确的元素顺序。

    而且 **hash **函数，它计算出的值依赖 table_size。也就是说，哈希表自动扩容后，同一个 key 的哈希值可能变化，即这个 key-value 对儿存储在 table 的索引也变了，所以遍历结果的顺序就和之前不一样了。

  2. 在遍历哈希表的过程中增删键值对是不安全的。

    当你在遍历一个哈希表时，如果进行插入或删除操作，可能会导致以下几种情况：

    1. 插入操作：通常不会使现有的迭代器失效，但会改变哈希表的内部状态（例如触发再散列），这可能导致遍历顺序的变化。
    2. 删除操作：删除当前迭代器指向的元素会使该迭代器失效。如果你继续使用失效的迭代器，会导致未定义行为。

  3. key 必须是不可变类型。所谓不可变类型，就是说这个对象一旦创建，它的值就不能再改变了。

    因为哈希表的主要操作都依赖于哈希函数计算出来的索引，如果 key 的哈希值会变化，会导致键值对意外丢失，产生严重的 bug。

一个巧妙的方法就是把 A 接到 B 的后面，把 B 接到 A 的后面。如果这样进行拼接，就可以让 p1 和 p2 同时进入公共部分，也就是同时到达相交节点 c1：

具体做法如下：

  • 每步操作需要同时更新指针 pA 和 pB。

  • 如果指针 pA 不为空，则将指针 pA 移到下一个节点；如果指针 pB 不为空，则将指针 pB 移到下一个节点。

  • 如果指针 pA 为空，则将指针 pA 移到链表 headB 的头节点；如果指针 pB 为空，则将指针 pB 移到链表 headA 的头节点。

两个链表在组合以后，长度是一样的。如果没有相交，那么一定会在某一时候同时到达 null，而 while 循环的条件就会不成立，跳出，返回 p1（p1 此时也是指向 null）。

167. 两数之和 II - 输入有序数组

重要：⭐⭐

题目要求额外空间必须是常数级，所以不能使用哈希表。但数组是一个有序数组，这是优化时可以利用的一个关键点。

解法一：暴力解法

最简单的解法就是两层循环遍历整个数组，外循环固定 index1，内循环在 index1 的右侧暴力查找 index2。

时间复杂度为 O(N2N^2N2)。这种解法其实不关心数组是否有序，因为在内层循环中，它是逐个比较来查找 index2。这个时间复杂度太高，实际上会超时。

那么如果我们想要优化这个算法，就必须从数组有序这个条件入手。数组有序，而且要查找元素，很自然的就能想到二分查找。

解法二：二分查找

外层循环不变，但是内层在查找 index2 时，使用二分查找进行优化，即在 [i+1, numbers.size()-1] 范围内使用二分查找寻找满足条件的 index2。

外层循环执行 n 次，每次内层二分查找的时间复杂度是 O(log⁡n)，所以总的时间复杂度是 O(n⋅logn)。

解法三：双指针

定义两个指针 left 和 right 分别指向数组的第一个元素和最后一个元素，计算当前指针所指的两个数之和 sum：

  • 如果 sum == target，找到了满足条件的两个数。
  • 如果 sum < target，说明需要更大的数来达到目标值，因此将左指针 left 向右移动一位。
  • 如果 sum > target，说明需要更小的数来接近目标值，因此将右指针 right 向左移动一位。

算法的时间复杂度为 O(n)，空间复杂度为 O(1)，非常高效。关键问题是，怎么证明这个算法不会遗漏可能的解？

由于数组是升序的，双指针算法旨在逐步缩小搜索范围。每次移动指针时，都会排除一部分不可能的解：

  • 如果 numbers[left] + numbers[right] < target，则 left 左边的数与 right 的和都会小于 target，因此可以排除 left 和它左边的所有数。
  • 如果 numbers[left] + numbers[right] > target，则 right 右边的数与 left 的和都会大于 target，因此可以排除此时 right 和它右边的所有数。

通过这种排除法，双指针算法能够确保不会遗漏任何可能的解。

这道题要求原地修改数组，所以不能新建数组。我们使用快慢指针，slow 作为新数组（不重复元素）的右边界，fast 在前面查找不重复的元素。

    • 如果 nums[fast] != nums[slow]，说明 nums[fast] 是一个新的不重复元素，将其放到 slow + 1 的位置，并移动 slow。
    • 如果 nums[fast] == nums[slow]，说明 nums[fast] 是重复元素，跳过它。
  3. 返回
    • 返回 slow + 1 就是新数组的长度。

  • 如果 nums[left] == val，则需要用 nums[right] 替换 nums[left]：
    • 如果 nums[right] != val，说明可以替换，将 nums[right] 赋值给 nums[left]，然后移动 left 和 right 指针。
    • 如果 nums[right] == val，说明不能直接替换，移动 right 指针往左。
      最后，返回 left 就是去除所有 num 元素的新数组了。

[!warning] 为什么循环的条件是是 left <= right 而不是 left < rifht？
这里容易犯的错就是循环的条件写不对，关键在于要不要加 left == right。如果 left == right，说明此时已经没有别的元素可以跟 nums[left] 交换了。但是此时我们并没有对 nums[left] 进行检查（left 的定义是指向当前需要检查的元素），我们还不知道这个数是不是等于 val，是不是要被移除？如果此时终止循环就会导致 return 的结果不准确。所以循环的条件必须是 left <= right 而不是 left < right。

解法二：中心扩展法

中心扩展法的思想是：枚举所有可能得回文子串的中心位置，以它为中心向两边扩展，找到最长的回文子串。中心位置可以是一个字符，也可以是两个字符。

对于每个可能的中心点（单个字符或两个相邻字符），尝试向两边扩展，直到不再满足回文条件。从中心往两边扩展查找回文子串的方法也很简单，只需要比对往两边扩展的新字符是否相等即可。因为中心位置有可能是单个字符，也有可能是两个字符，所以我们需要统一处理，expandAroundCenter 函数的形参总共需要传递 3 个参数。

时间复杂度：

  • 总体时间复杂度为 O(n2)O(n^2)O(n2)。

思路：首先使用split函数将原路径按照 / 进行分割，得到一个字符串数组。这个字符串数组中的字符串只会存在以下几种情况：

  • 对于「空字符串」以及「一个点」，我们实际上无需对它们进行处理，因为「空字符串」没有任何含义，而「一个点」表示当前目录本身，我们无需切换目录。

20. 有效的括号

判断括号的有效性可以使用「栈」这一数据结构来解决。

我们遍历给定的字符串 s。当我们遇到一个左括号时，我们会期望在后续的遍历中，有一个相同类型的右括号将其闭合。由于后遇到的左括号要先闭合，因此我们可以将这个左括号放入栈顶。

当我们遇到一个右括号时，我们需要将一个相同类型的左括号闭合。此时，我们可以取出栈顶的左括号并判断它们是否是相同类型的括号。如果不是相同的类型，或者栈中并没有左括号，那么字符串 s 无效，返回 False。为了快速判断括号的类型，我们可以使用哈希表存储每一种括号。哈希表的键为右括号，值为相同类型的左括号。

在遍历结束后，如果栈中没有左括号，说明我们将字符串 s 中的所有左括号闭合，返回 True，否则返回 False。

注意到有效字符串的长度一定为偶数，因此如果字符串的长度为奇数，我们可以直接返回 False，省去后续的遍历判断过程。

150. 逆波兰表达式求值

逆波兰表达式由波兰的逻辑学家卢卡西维兹提出。逆波兰表达式的特点是：没有括号，运算符总是放在和它相关的操作数之后。因此，逆波兰表达式也称后缀表达式。

逆波兰表达式严格遵循「从左到右」的运算。计算逆波兰表达式的值时，使用一个栈存储操作数，从左到右遍历逆波兰表达式，进行如下操作：

  • 如果遇到操作数，则将操作数入栈；

  • 如果遇到运算符，则将两个操作数出栈，其中先出栈的是右操作数，后出栈的是左操作数，使用运算符对两个操作数进行运算，将运算得到的新操作数入栈。

整个逆波兰表达式遍历完毕之后，栈内只有一个元素，该元素即为逆波兰表达式的值。

二叉树

二叉树算法核心纲领

二叉树解题的思维模式分两类：

1、是否可以通过遍历一遍二叉树得到答案？如果可以，用一个 traverse 函数配合外部变量来实现，这叫「遍历」的思维模式。

2、是否可以定义一个递归函数，通过子问题（子树）的答案推导出原问题的答案？如果可以，写出这个递归函数的定义，并充分利用这个函数的返回值，这叫「分解问题」的思维模式。

无论使用哪种思维模式，你都需要思考：

如果单独抽出一个二叉树节点，它需要做什么事情？需要在什么时候（前/中/后序位置）做？其他的节点不用你操心，递归函数会帮你在所有节点上执行相同的操作。

前中后序是遍历二叉树过程中处理每一个节点的三个特殊时间点，绝不仅仅是三个顺序不同的 List：

  • 前序位置的代码在刚刚进入一个二叉树节点的时候执行；
  • 后序位置的代码在将要离开一个二叉树节点的时候执行；
  • 中序位置的代码在一个二叉树节点左子树都遍历完，即将开始遍历右子树的时候执行。


二叉树的所有问题，就是让你在前中后序位置注入巧妙的代码逻辑，去达到自己的目的，你只需要单独思考每一个节点应该做什么，其他的不用你管，抛给二叉树遍历框架，递归会在所有节点上做相同的操作。

后序位置的特殊之处

仔细观察，前中后序位置的代码，能力依次增强。

  • 前序位置的代码只能从函数参数中获取父节点传递来的数据。
  • 中序位置的代码不仅可以获取参数数据，还可以获取到左子树通过函数返回值传递回来的数据。
  • 后序位置的代码最强，不仅可以获取参数数据，还可以同时获取到左右子树通过函数返回值传递回来的数据。

所以，某些情况下把代码移到后序位置效率最高；有些事情，只有后序位置的代码能做。一旦你发现题目和子树有关，那大概率要给函数设置合理的定义和返回值，在后序位置写代码了。

利用后序位置的题目，一般都使用「分解问题」的思路。因为当前节点接收并利用了子树返回的信息，这就意味着你把原问题分解成了当前节点 + 左右子树的子问题。

543. 二叉树的直径

重要程度：⭐⭐

二叉树的 直径 是指树中任意两个节点之间最长路径的 长度 。这条路径可能经过也可能不经过根节点 root 。两节点之间路径的 长度 由它们之间边数表示。

解决这题的关键在于，当前根节点的「直径」长度，就是左右子树的最大深度之和。

我们利用求解二叉树最大深度的思路，递归过程中顺便更新每个节点的直径，并选出最大的就是答案。

更新最大直径和求最大深度的代码还是在后序位置，因为只有在这里，我们才能同时获取到左右子树递归返回的信息。

时间复杂度 O(N)。

复杂度分析

  2. 空间复杂度：O(N)（vector 存储所有节点 + 递归栈空间）。

解法二：存储前驱节点+先序遍历递归+原地修改。

相比上一个解法，存储整个先序序列，我们实际上只需要每次存储前一个节点（prev）即可，在递归的同时就可以修改指针完成链表。这样做只需要一次遍历，也不需要额外空间存储所有节点，原地修改。

核心逻辑是通过前序遍历递归地修改指针关系：

  • 每次访问一个节点时，将前驱节点 prev 的右指针指向当前节点 root，并清空左指针。
  • 然后更新 prev 为当前节点 root，继续递归处理其左右子树。

需要注意的是，因为是原地修改二叉树，递归 root->left 时，可能会修改 root->right 的指向，因此必须提前保存 root->right，否则递归返回时会丢失原始的右子树。而左子树的引用 root->left 会被递归处理，递归结束后其指针关系已经被正确展开，不需要额外保存 root->left。

复杂度分析：

  1. 时间复杂度：O(N)（遍历一次）。
  2. 空间复杂度：O(N)（递归栈空间，无额外 vector 存储）。

解法三：寻找前驱节点

前面的方法方法前序遍历过程中需要使用额外的存储空间存储节点（辅助数组或递归栈）。有没有空间复杂度是 O(1) 的做法呢？

前序遍历访问各节点的顺序是根节点、左子树、右子树。如果根节点的左子树为空，那么什么也不用做。如果根节点的左子树不为空，访问完所的左子树之后，才会去访问右子树。左子树最后一个被访问的节点是它右下角的那个节点，右子树被访问的第一个节点就是右子树的根节点，那么我们称左子树右下角的那个节点为前驱节点。

算法思路：对于每个有左子树的节点：

  • 找到左子树中最右边的节点（前驱）
  • 将前驱的右指针连接到当前节点的右子树
  • 将右指针指向左子树（不用担心右子树找不到，它已经被连接到前驱）
  • 将左指针置空

这样，就避免了使用栈或递归，空间效率很高。

复杂度分析：

  • 时间复杂度：O(N)，n是节点数
  • 空间复杂度：O(1)，使用常量额外空间

  1. 创建一个根节点，其值为 nums 中的最大值。
  2. 递归地在最大值 左边 的 子数组前缀上 构建左子树。
  3. 递归地在最大值 右边 的 子数组后缀上 构建右子树。

返回 nums 构建的 最大二叉树 。

题解：题目中其实已经把解法的过程说得很清楚了。按照原题的流程构建递归函数即可。

复杂度分析：

  • 时间复杂度：O(n2)O(n^2 )O(n2)，其中 n 是数组 nums 的长度。在最坏的情况下，数组严格递增或递减，需要递归 n 层，第 i (0≤i<n) 层需要遍历 n−i 个元素以找出最大值，总时间复杂度为 O(n2)O(n^2)O(n2)。
  • 空间复杂度：O(n)O(n)O(n)，即为最坏情况下需要使用的函数递归栈空间。

105. 从前序与中序遍历序列构造二叉树

给定两个整数数组 preorder 和 inorder ，其中 preorder 是二叉树的先序遍历， inorder 是同一棵树的中序遍历，请构造二叉树并返回其根节点。

题解：

对于任意一颗树而言，前序遍历的形式总是[ 根节点, [左子树的前序遍历结果], [右子树的前序遍历结果] ] ，即根节点总是前序遍历中的第一个节点。

而中序遍历的形式总是 [ [左子树的中序遍历结果], 根节点, [右子树的中序遍历结果] ]，只要我们在中序遍历中定位到根节点，那么我们就可以分别知道左子树和右子树中的节点数目。

复杂度分析

  • 时间复杂度：O(n)，其中 n 是树中的节点个数。
  • 空间复杂度：O(n)

297. 二叉树的序列化与反序列化

序列化是将对象、数据结构或其他复杂数据类型转换为一种可存储或传输的格式的过程。通常，这个格式是线性的、连续的字节流（如字符串、字节数组、JSON、XML等），方便在文件系统中保存或通过网络发送。

反序列化是序列化的逆过程，即将序列化后的数据（如字节流或字符串）重新转换回原始的对象或数据结构。

请设计一个算法来实现二叉树的序列化与反序列化。这里不限定你的序列 / 反序列化算法执行逻辑，你只需要保证一个二叉树可以被序列化为一个字符串并且将这个字符串反序列化为原始的树结构。

如果二叉树中的节点值不重复，那么根据序列化信息还原二叉树可以分为两种情况：

  1. 序列化结果中不包含空指针信息（即只存储节点值）：

    • 仅提供一种遍历顺序：
      • 无法还原出唯一的二叉树。
    • 提供两种遍历顺序：
      • 前序 + 中序：可以唯一还原二叉树。
      • 后序 + 中序：可以唯一还原二叉树。
      • 前序 + 后序：无法唯一还原二叉树（因为无法确定左右子树的划分）。

  2. 序列化结果中包含空指针信息（如用特殊标记表示空节点）：

    • 仅提供一种遍历顺序：
      • 前序或后序：可以唯一还原二叉树（因为空指针信息可以明确树的结构）。
      • 中序：无法唯一还原二叉树（即使有空指针信息，也无法确定根的位置）。

题目中要求我们将二叉树序列化成为一个字符串，那么为了减少时间复杂度，我们应该尽可能地少遍历次数。提供前序或后序遍历序列，并包含空指针，是理想的解决方法。

652. 寻找重复的子树

给你一棵二叉树的根节点 root ，返回所有 重复的子树 。

对于同一类的重复子树，你只需要返回其中任意 一棵 的根结点即可。

如果两棵树具有 相同的结构 和 相同的结点值 ，则认为二者是 重复 的。

示例 1：

输入：root = [1,2,3,4,null,2,4,null,null,4]
输出：[[2,4],[4]]

题解：使用序列化进行唯一表示。

将每一棵子树都「序列化」成一个字符串，并且保证：

  • 相同的子树会被序列化成相同的子串；
  • 不同的子树会被序列化成不同的子串。

那么我们只要使用一个哈希表存储所有子树的序列化结果，如果某一个结果出现了超过一次，我们就发现了一类重复子树。

直接说结论，在解决二叉树的所有路径问题时，我们优先使用先序遍历（根 -> 左 -> 右）。原因如下：

  1. 路径是从根节点到叶子节点的，所以我们需要先访问根节点，再递归处理左、右子树。

  2. 先序遍历天然适合记录路径，因为：

    • 我们先访问当前节点，把它的值加入路径。

    • 然后递归左、右子树，如果遇到叶子节点（左右子树均为空），就把当前路径加入结果。
