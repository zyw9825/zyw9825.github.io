基础暴力算法

发表于2025-09-27|更新于2025-01-15|算法
|浏览量:

简介

动态规划（Dynamic Programming，简称 DP）是一种用于解决复杂问题的优化算法。它通过将问题分解为更小的子问题，并存储这些子问题的解以避免重复计算，从而高效地解决问题。

动态规划问题的一般形式就是求最值，求解动态规划的核心问题是穷举。

动态规划遵循一套固定的流程：递归的暴力解法 -> 带备忘录的递归解法 -> 非递归的动态规划解法。

核心思想

  1. 分解子问题：将原问题拆解为更小的、相互关联的子问题。
  2. 存储中间结果：用数组或哈希表记录子问题的解，避免重复计算。
  3. 递推求解：基于子问题的解，逐步推导出原问题的解。

基本要素

  1. 最优子结构：原问题的最优解包含子问题的最优解，可以通过小问题的最优解推导出大问题的最优解。

    • 例：最短路径问题中，A→C 的最短路径 = A→B 的最短路径 + B→C 的最短路径。

  2. 重叠子问题：子问题会被多次重复计算。

    • 子问题是原大问题的小版本，它们的计算步骤完全一样。计算大问题的时候，需要多次重复计算小问题。这就是重叠子问题。

    • 一个子问题的多次计算，耗费了大量时间。用 DP 处理重叠子问题，每个子问题只需要计算一次，从而避免了重复计算，这就是 DP 效率高的原因。

    • 例：斐波那契数列中，计算 fib(5) 需要多次计算 fib(2)。

步骤

  1. 定义状态：明确问题的状态表示，通常用 dp[i] 或 dp[i][j] 表示某个子问题的解。
  2. 确定状态转移方程：找出状态之间的关系，即如何从已知状态推导出未知状态。
  3. 初始化和边界条件：设定初始值或边界条件，确保递推过程能够正确开始。
  4. 计算顺序：自底向上（迭代）或自顶向下（递归+备忘录）。
  5. 优化空间（可选）：如果状态转移只依赖有限的前几个状态，可以压缩存储空间。

自底向上的递推

备忘录+递归的方式就是动态规划的自顶向下模式，我们可以转换为更常见地自底向上的递推模式。

过程是类似的，只不过把过程“倒”过来。我们可以把这个「备忘录」独立出来成为一张表，通常叫做 DP table，只需要完成这张表，就能得到我们想要的结果。DP table 需要进行初始化，然后通过状态转移方程进行递推。

在斐波那契数列的数学定义中，$F (N) = F (N-1) + F (N-2) $ 就是状态转移方程。状态转移方程就是动态规划的核心，本质上还是穷举。

优化存储空间

动态规划的最后一步就是优化存储空间，这一步是可选的，一般不做强制要求。

在递推过程中，如果状态转移只依赖有限的前几个状态，可以压缩存储空间。也就是说，递推时不需要保存所有之前记录的结果，只保留状态转移所需要的几个有限的状态即可。这样就可以大大减少存储空间，减少空间复杂度。

就斐波那契数列来说，状态转移之和前两次的状态有关，所以，我们只需要每次记录并更新前两次的状态即可。

存储空间从 O(n)O(n)O(n) 优化到 O(1)O(1)O(1)，这就是斐波那契数列最常见的写法。

斐波那契数列的例子严格来说不算动态规划，因为没有涉及求最值，但方便讲解重叠子问题。

最优子结构

凑零钱就是典型的动态规划问题，自然也符合最优子结构，即问题的最优解可以通过其子问题的最优解来构造。通俗来说，如果一个问题可以分解为若干个子问题，并且每个子问题的最优解能够组合成整个问题的最优解，那么这个问题就具有最优子结构性质。

在示例 1 中，如果我们要求 amount = 11 时的最少硬币数，如果你知道凑出 amount = 10, 9, 6 的最少硬币数（子问题），你只需要把子问题的答案加一（再选一枚面值为 1, 2, 5 的硬币），再求个最小值，就是原问题的答案。因为硬币的数量是没有限制的，所以子问题之间没有相互制约，是互相独立的。

状态与状态转移方程

状态是指问题在某一阶段的特征或关键信息，它能够唯一地描述当前问题的状态。

  1. 明确「状态」，一般是原问题和子问题中会变化的变量。在凑零钱的例子中，从原问题到子问题，目标金额不断向 base case 靠近，所以状态就是目标金额 amount
  2. 明确 「选择」，也就是导致「状态」产生变化的行为。每选择一枚硬币，就相当于减少了目标金额 amount，所以，所有硬币的面值，就是「选择」。
  3. 明确 dp 函数/数组的定义。在自顶向下的解法中，会有一个递归的 dp 函数。一般来说函数的参数就是状态转移中会变化的量，也就是上面说到的「状态」；函数的返回值就是题目要求我们计算的量。就本题来说，状态只有一个，即「目标金额」，题目要求我们计算凑出目标金额所需的最少硬币数量。所以我们可以这样定义 dp 函数：
    • dp(n) 表示，输入一个目标金额 n，返回凑出目标金额 n 所需的最少硬币数量。

[!IMPORTANT]

为啥 dp 数组中的值都初始化为 amount + 1 呢？

amount + 1 在这里相当于正无穷，表示不可能的最大取值，因为凑成 amount 金额的硬币数最多需要 amount 个一元硬币，这就是最大值。初始化为不可达的最大值，方便后面比较选出硬币数最小的方案。这里不写成 INT_MAX 是因为后面有 dp[i - coin] + 1，这就会导致整型溢出。

现在回过头看自底向上的递推形式的动态规划，我们实际上就是做了穷举这么一件事：我们计算出从 0 ~ amount 中间所有金额的最少硬币数。我们给出了 base case，然后通过状态转移方程推出其它金额。算法设计无非就是先思考「如何穷举」，然后再追求「如何聪明地穷举」。

背包问题

0-1 背包问题

问题描述

给定 N 个物品，每个物品有对应的重量和价值，比如第 i 个物品的重量为 weight[i-1]，价值为 value[i-1]。同时给定一个背包的最大承重（容量）W。每个物品只能选择放入或不放入背包（即“0-1”表示不能部分放入）。每个物品只能用一次，在不超过背包容量的前提下，最多能装的价值是多少？

题解

这个问题中的状态有两个，一个是重量，一个是价值，所以我们需要维护一个二维数组表示状态，定义如下：

dp[i][j] 表示前 i 个物品（物品编号从 1 到 i）在背包容量为 j 时可以获得的最大价值。

举个例子，dp[3][5] = 10 表示前 3 个（编号 1，2，3）物品在背包容量为 5 时最多能装下的价值为 10。

根据这个定义，原问题的答案就是 dp[N][W] 的值，即前 N 个物品在背包容量为 W 时获得的最大价值。初始化时，当没有物品（i = 0）或背包容量为 0（w = 0）时，最大价值为 0，即 dp[0][j] = 0 和 dp[i][0] = 0。

要返回 dp[N][W] 那么我们就声明 dp 就是一个 N+1 行 W+1 列的二维数组。

每个物品只能选择放入或不放入背包，对于每个物品 i，有两种选择：

  1. 不放入背包：
    • 如果不放入第 i 个物品，则最大价值等于前 i-1 个物品在容量 j 时的最大价值。
    • 即：dp[i][j] = dp[i-1][j]。
  2. 放入背包：
    • 放入后的最大价值等于前 i-1 个物品在容量 j - weights[i-1] 时的最大价值，加上当前物品的价值 values[i-1]。
    • 即：dp[i][j] = dp[i-1][j - weights[i-1]] + values[i-1]。
    • 那么，如果想放入第 i 个物品，必须要保证 j - weights[i-1] >= 0。

这两种选择都可以，需要进行择优，选出价值最大的。

优化存储空间

在上面的实现中，我们使用了二维数组来表示状态，但是实际上 dp[i][j] 的更新只依赖于 dp[i - 1][j] 和 dp[i - 1][j - weight[i - 1]]，也就是说，当前行的值只依赖于上一行的值，而与更早的行无关。

因此，我们不需要保存整个二维数组，只需要保存 上一行 的值即可。通过滚动数组的方式，可以将二维数组优化为一维数组。

我们可以用一个一维数组 dp[j] 来代替二维数组 dp[i][j]，dp[j] 表示容量为 j 时的最大价值。

在更新 dp[j] 时，我们只需要用到 dp[j] 和 dp[j - weight[i]]。所以我们需要 从后向前更新，确保在更新 dp[j] 时，dp[j - weight[i]] 仍然是上一行的值。

内层循环的条件 j >= weight[i] 保证了 j - weight[i] 始终是非负的，不会越界。因此，代码中不需要额外的判断 j 和 weight[i] 的值。这样做是因为，对于 j < weight[i] 的 dp[j]，它的值本来就是上一行的 dp[j]，即对应上一个解法的 dp[i][j] = dp[i - 1][j]，所以不需要再遍历。

分析

这个问题是传统 0-1 背包问题的变体。这道题可以换一种表述：

  • 给定一个只包含正整数的非空数组 nums，判断是否可以从数组中选出一些数字，使得这些数字的和等于整个数组的元素和的一半。

这道题与传统的「0−1 背包问题」的区别在于，传统的「0−1 背包问题」要求选取的物品的重量之和不能超过背包的总容量，这道题则要求选取的数字的和恰好等于整个数组的元素和的一半。但解法都是一样的，都是使用动态规划，慢慢扩大数组范围和目标值，最终推出答案。

和 0-1 背包问题类似，我们这样定义 dp 数组：

  • dp[i][j] 表示前 i 个数（nums[0]~nums[i-1]）中是否能够选出一些数，使得这些数的和恰好为 j。

在定义状态以后，需要考虑边界情况。

  • dp[0][j] 表示不选择任何数，那么只有当 j = 0 时成立，即 dp[0][0] = true，其余情况都不成立：dp[0][j] = false (j > 0)；
  • dp[i][0] 表示是否能选出一些数，使得它们的和为 0。这当然是可以的，对于任意的 i，只要我们一个数都不选，它们的和自然是 0。所以，dp[i][0] = true。

现在讨论返回值：我们假设数组 nums 的大小为 n，nums 中所有数的和为 sum，那么我们求解的目标就是：num 中前 n 个数，能否选出一些数，它们的和加起来等于 sum/2，对应 dp[n][sum/2]。

刚才已经讨论了 i=0 或 j=0 时的情况，那么对于 i > 0, j > 0 的情况，该如何进行状态转移？

在更新 dp[i][j] 时，意味着我们要将 nums 数组的考虑范围从 [0,i−2][0, i-2][0,i−2]（共 i−1i - 1i−1 个数）扩大到 [0,i−1][0, i-1][0,i−1]（共 iii 个数）。对于整数 nums[i-1]，我们需要分情况讨论：

  • 如果 j >= nums[i-1]，则对于当前的数字 nums[i-1]，可以选取也可以不选取，两种情况只要有一个为 true，就有 dp[i][j] = true。
    • 如果不选取 nums[i-1]，则 dp[i][j] = dp[i−1][j]；
    • 如果选取 nums[i-1]，则 dp[i][j] = dp[i−1][j−nums[i-1]]。
  • 如果 j < nums[i-1]，此时 nums[i-1] 必不能选，那么 dp[i][j] = dp[i−1][j]。

题解

优化存储空间

dp[i][j] 都是通过上一行 dp[i-1][..] 转移过来的，所以可以将二维 dp 数组压缩为一维，节约空间复杂度。同时注意 j 要从右往左遍历，防止覆盖数据。

考虑边界情况：

  • dp[i][0]，当 i=0 时，d[0][0] = 1，也就说什么都不选（这也是一种组合方式），和自然就是 0 了。当 i 不等于 0 时，就没法确定了。
  • dp[0][j]，当 j 不等于 0 时，dp[0][j] = 0。

考虑状态转移方程，对于 nums[i-1] 来说，有放入和不放入（背包问题的说法）两种选择，那么总的组合方式就应该是二者之和：

  • dp[i][j] = dp[i-1][j] + dp[i-1][j - num[i-1]] 此时应满足 j >= num[i-1]

对于 j < nums[i-1] 的情况，就只有不放入这一种选择了，所以：

  • dp[i][j] = dp[i-1][j] （j < nums[i-1]）

状态转移完毕后，我们返回 dp[n][(target + sum (nums)) / 2] 就是正确答案。

当然，在进行状态转移之前，还需要对输入进行一些判断，这部分直接看代码。

完全背包问题

前面已经介绍过 323. 零钱兑换 问题，是一个经典的动态规划问题。现在来看 518. 零钱兑换 II：

给你一个整数数组 coins 表示不同面额的硬币，另给一个整数 amount 表示总金额。

请你计算并返回可以凑成总金额的硬币组合数。如果任何硬币组合都无法凑出总金额，返回 0 。

假设每一种面额的硬币有无限个。

题目数据保证结果符合 32 位带符号整数。

示例 3：

提示：

  • 1 <= coins. length <= 300
  • 1 <= coins[i] <= 5000
  • coins 中的所有值 互不相同
  • 0 <= amount <= 5000

分析

我们可以把这个问题转化为背包问题的描述形式：

  • 有一个背包，最大容量为 amount，有一系列物品 coins，每个物品的重量为 coins[i]，每个物品的数量无限。请问有多少种方法，能够把背包恰好装满？

这个问题是典型的完全背包问题，完全背包问题的特点是：

  1. 物品无限：每种硬币可以选无限次。
  2. 组合不考虑顺序：1+2 和 2+1 视为同一种组合。

按照前面背包问题的套路，状态有两个：「背包的容量」和「可选择的物品」，选择就是「装进背包」或者「不装进背包」。

我们使用二维数组 dp[i][j] 表示状态，并对状态作如下定义：

  • dp[i][j] 表示如果只使用前 i 种硬币（可重复使用），能凑出总金额为 j 的组合数。

现在考虑边界情况：

  • dp[i][0] = 1 ：要凑出总金额为 0，只有一种组合数，即什么都不选；
  • dp[0][j] = 0, j > 0：什么都不选，对于任何大于 0 的总金额，组合数都是 0。

现在考虑状态转移方程。对于 dp[i][j]，现在把 coins[i-1] 纳入考虑范围：

  • 如果 j >= coins[i-1]，表示可以选择把面值为 coins[i-1] 的硬币加入组合，也可以选择不加入组合，那么 dp[i][j] 就应该是二者之和。即：dp[i][j] = dp[i-1][j] + dp[i][j-coins[i-1]]；

  • 如果 j < coins[i-1] ，那么面值为 coins[i-1] 的硬币就没法用，这个时候，dp[i][j] = dp[i-1][j]。

最终，我们要求的是使用所有硬币凑出 amount 的组合数，假设 coins 数组的大小是 n，那么只需要返回 dp[n][amount] 即可。

题解

优化存储空间

dp 数组的转移只和 dp[i][..] 和 dp[i-1][..] 有关，所以可以进一步压缩存储空间：

[!WARNING]

虽然同时遍历二维数组，但是哪个在外层，哪个在内层，是不能乱写的。就本题来说，必须要外层遍历硬币，内层正向遍历金额。

核心目标是组合唯一性：完全背包要求计算的是组合数（如 1+2 和 2+1 视为同一种组合），而非排列数。

外层遍历硬币，硬币按固定顺序处理，确保组合中硬币的排列顺序唯一（如 [1,2] 只能按 1 在前、2 在后的顺序生成）。

如果外层遍历金额，内层遍历硬币，每个金额 j 的处理会遍历所有硬币，导致同一金额可能被不同硬币多次更新，而这就会失去组合唯一性，比如：对于 j=3，可能先通过 coin=1 得到 1+2，再通过 coin=2 得到 2+1，这两个结果会被视为不同组合，导致结果错误。

编辑距离

力扣72.编辑距离

给你两个单词 word1 和 word2，请返回将 word1 转换成 word2 所使用的最少操作数。

你可以对一个单词进行如下三种操作：

  • 插入一个字
  • 删除一个字符
  • 替换一个字符

示例 1：

[!TIP]

在解决涉及两个字符串的动态规划问题时，我们通常使用两个索引或指针（记作 i 和 j）来遍历这两个字符串。这种方法可以用于计算编辑距离、最长公共子序列等问题。

一种常见的方法是让 i 和 j 分别从各自字符串的尾部开始，逐步向头部移动。在这种情况下，我们可以定义 dp[i][j] 为第一个字符串 s1 从起始位置到第 i 个字符与第二个字符串 s2 从起始位置到第 j 个字符之间的某种关系。

这意味着，当我们逐步减少 i 和 j 的值时，实际上是在减小子问题的规模，即考虑越来越短的子串。

当然，从头部往尾部移动也是可以的。

来看一个动图，把字符串 s1 变成字符串 s2：

我们从右往左遍历两个字符串，如果 i 和 j 所指的字符本来就相等，那么就跳过，我们什么都不用做。i 和 j 都左移。

如果 i 和 j 所指的字符不相等，那么我们有 3 种选择：

  1. 删除：删除 s1 字符串 i 所指的字符。i 左移，j 不动。
  2. 插入：在 i+1 的位置插入 j 所指的字符。i 不同，j 左移。
  3. 替换：将 i 所指的字符替换成 j 所指的字符。i 和 j 都左移。

在极端情况下，如果 j 已经走完了 s2，但是 i 还有走完 s1，那么只需把 0~i 的字符全部删掉。

那么我们按照上面的思路，就不难写出递归代码。因为要编辑距离最小，我们在每次选择时选出删除、插入、替换中操作最少的一个即可。

递归

带备忘录的递归

上一个方法是纯递归，存在大量的重复计算。我们可以加入备忘录，查询时先查备忘录，如果没有再计算：

动态规划

因为涉及到两个字符串 s1 和 s2，所以 dp 数组是二维的。我们这样定义：

  • dp[i][j] 表示从 s1 中前 i 个字符（s1[0,..., i-1]）到 s2 中前 j 个字符（s2[0,..., j-1]）的最小编辑距离。

那么按照前面的推理，考虑边界情况：

  • dp[0][j] = j
  • dp[i][0] = i

最后，我们返回 dp[s1.size ()][s2.size ()] 即可。

动态规划滚动数组版

dp[i][j] 只与它周围的四个值有关，包括本行的一个值和上一行的两个值。那么我们可以把二维数组优化成两个一维数组。

最大连续子序列和

给你一个整数数组 nums ，请你找出一个具有最大和的连续子数组（子数组最少包含一个元素），返回其最大和。

子数组是数组中的一个连续部分。

示例 1：

动态规划

注意子数组中的元素是连续的。我们这样定义 dp：

  • dp[i] 表示以 nums[i] 结尾的连续子数组的最大和。

那么 base case 就是 dp[0] = nums[0]，从左往右遍历，对于 dp[i]，其实有两种选择：

  1. 加入前一个子数组：dp[i] = dp[i-1] + nusm[i]
  2. 从自己开始创建一个新的子数组：dp[i] = nums[i]

按照对 dp table 的定义，我们需要选出最大的。最后，返回 dp 中的最大值，就表示原数组 nums 中的连续子数组最大和。

  • 时间复杂度为 O (n)，只需要遍历数组一次。
  • 空间复杂度为 O (n)，使用了一个长度为 n 的数组 dp 来存储中间结果。

这个题也可以优化存储空间，可以发现 dp[i] 其实只和 dp[i-1] 和 nums[i] 有关。所以只需要用一个数记录 dp[i-1] 即可。这样可以将空间复杂度优化到 O (1)。

贪心

贪心算法的核心思想是在每一步选择中都做出在当前看来最优的选择，从而希望最终结果也是最优的。

对于这个问题，我们可以维护一个当前子数组的和 currentSum，并在遍历数组时不断更新这个和。

对于每个元素 num：

  • 如果 currentSum < 0，说明当前子数组的和已经对后续结果没有贡献（因为负数会拖累和），所以从当前元素重新开始，即 currentSum = num。
  • 如果 currentSum >= 0，则将当前元素加入到当前子数组中，即 currentSum += num。
  • 时间复杂度：O (n)，其中 n 是数组的长度。因为只需要遍历数组一次。
  • 空间复杂度：O (1)，只使用了常数个额外变量。

最长公共子序列 LCS

力扣：1143 最长公共子序列

给定两个字符串 text1 和 text2，返回这两个字符串的最长 公共子序列 的长度。如果不存在 公共子序列 ，返回 0 。

一个字符串的 子序列 是指这样一个新的字符串：它是由原字符串在不改变字符的相对顺序的情况下删除某些字符（也可以不删除任何字符）后组成的新字符串。

  • 例如，"ace" 是 "abcde" 的子序列，但 "aec" 不是 "abcde" 的子序列。

两个字符串的 公共子序列 是这两个字符串所共同拥有的子序列。

示例 1：

分析

最长公共子序列问题是典型的二维动态规划问题。我们这样定义 dp：

  • dp[i][j] 表示 text1[0... i-1] 和 text2[0... j-1] 的最长公共子序列的长度。

数组 dp 的维度是 (m+1) × (n+1)，多出来的第 0 行和第 0 列是为了方便初始化（表示空字符串的情况）。空字符串和任何字符串的最长公共子序列的长度都是 0，所以有 base case：

  • dp[i][0] = 0
  • dp[0][j] = 0

要求 dp[i][j]，即 text1[0... i-1] 和 text2[0... j-1] 的最长公共子序列的长度，我们假设 c1 = text1[i-1]，c2 = text2[i-1]，那么有：

  1. 如果当前字符相同（c1 == c2），将这两个相同的字符称为公共字符，考虑 text1[0... i-2] 和 text2[0... j-2] 的最长公共子序列的长度，再增加一个字符（即公共字符）就可以得到 dp[i][j]。所以有：

    • dp[i][j] = dp[i-1][j-1] + 1。

  2. 如果当前字符不同（c1 != c2），它们无法共同贡献到同一个公共子序列。考虑以下两项：

    • text1[0... i−1] 和 text2[0... j] 的最长公共子序列；
    • text1[0... i] 和 text2[0... j−1] 的最长公共子序列。

    要得到 text1[0... i] 和 text2[0... j] 的最长公共子序列，应取两项中的长度较大的一项，所以有：

    • dp[i][j] = max(dp[i-1][j], dp[i][j-1])。

最终计算得到 dp[m][n] 即为 text1 和 text2 的最长公共子序列的长度。

两个字符串的删除操作

583. 两个字符串的删除操作

给定两个单词 word1 和 word2 ，返回使得 word1 和 word2 相同所需的最小步数。

每步 可以删除任意一个字符串中的一个字符。

示例 1：

提示：

  • 1 <= word1. length, word2. length <= 500
  • word1 和 word2 只包含小写英文字母

分析

思路一：利用上面的最长公共子序列的解法，先求出两个字符串中的最长公共子序列的长度，我们已知两个字符串的长度，自然可以算出需要删除的次数。

思路二：动态规划。我们定义 dp 为 (m+1) × (n+1) 的二维数组：

  • dp[i][j] 表示使 word1[0... i-1] 和 word2[0... j-1] 相同的最少删除操作次数。

当其中一个字符串为空时（即 i=0 或 j=0），需要删除另一个字符串中的所有字符才能使两个字符串相同。因此：

  • dp[0][j] = j 对于所有的j
  • dp[i][0] = i 对于所有的i

状态转移：

  • 如果word1[i-1] == word2[j-1]，增加一个公共字符之后，最少删除操作次数不变。所有有：dp[i][j] = dp[i-1][j-1]。

  • 如果word1[i-1] != word2[j-1]，则有三种选择：

    1. 删除word1的最后一个字符，此时dp[i][j] = dp[i-1][j] + 1。
    2. 删除word2的最后一个字符，此时dp[i][j] = dp[i][j-1] + 1。
    3. 同时删除word1和word2的最后一个字符，此时dp[i][j] = dp[i-1][j-1] + 2。但因为我们要求删除次数最小，而 1，2 一定是小于或等于 3 的，所以 3 其实不必考虑。

    所以，省略第三种情况，此时有dp[i][j] = min(dp[i-1][j], dp[i][j-1]) + 1

[!NOTE]

为什么选择 3 不用考虑？

  • dp[i-1][j] <= dp[i-1][j-1] + 1恒成立，因为从 dp[i-1][j-1] 到 dp[i-1][j] 最多只需删除 word2[j-1]。
  • dp[i][j-1] <= dp[i-1][j-1] + 1恒成立，因为从 dp[i-1][j-1] 到 dp[i][j-1] 最多只需删除 word1[i-1]。

因此，dp[i-1][j-1] + 2（同时删除两个字符）永远不会比 dp[i-1][j] + 1 或 dp[i][j-1] + 1 更优。
