线程简介

一个线程指的是进程中一个单一顺序的控制流（或者说是执行路线、执行流），它被包含在进程之中，是进程中的实际运行单位。

任何一个进程都包含一个主线程，只有主线程的进程称为单线程进程。

多线程指的是除了主线程以外，还包含其它的线程。其它线程通常由主线程来创建，创建的新线程就是主线程的子线程。

在多线程应用程序中，一个进程包含了多个线程，每个线程都可以参与系统调度、被 CPU 执行。所以说，线程是程序最基本的运行单位，而进程不能运行，真正运行的是进程中的线程。

线程之间是可以共享大部分进程资源，比如内存空间（代码段、数据段、堆空间、动态库文件）、文件与 IO 资源（文件描述符、标准输入/输出/错误流）、信号处理、环境变量等资源。但每个线程都有自己独立的栈空间（线程栈 call stack）、寄存器环境（register context）和线程本地存储（thread-local storage）。

由于线程共享内存和资源，必须通过同步机制避免竞态条件。

[!important]
进程是资源分配的基本单位，线程是 CPU 调度的基本单位。

[!important] 为什么选择多线程而不是多进程？
多进程的劣势：

  • 进程间切换开销大。进程切换需要切换完整的虚拟内存空间（TLB 刷新、页表切换等）。

  • 进程间通信比较麻烦。进程间通信（IPC）需通过管道、消息队列、共享内存等，涉及内核态切换和数据拷贝，速度慢。

多线程的优势：

  • 更低的切换开销：同进程内的线程共享内存空间，线程切换时仅需保存寄存器状态和栈指针。

  • 更高效的通信机制：线程默认共享进程内存，可直接读写同一变量（需同步机制如互斥锁）。

  • 线程创建速度更快，且消耗资源更少。

  • 多线程在多个处理器上更有优势，可以充分利用现代 CPU 的并行计算能力。

参数解析：

  • thread ：输出参数，创建成功后，这个变量会包含新线程的 ID；
  • attr：线程属性，一般传 NULL 表示使用默认属性；
  • start_routine：线程要执行的函数的指针。线程创建后会从这个函数开始运行。该函数返回值类型为 void *，并且该函数的参数只有一个 void *，其实这个参数就是第四个参数 arg。如果需要向 start_routine() 传递的参数有一个以上，那么需要把这些参数放到一个结构体中，然后把这个结构体对象的地址作为 arg 参数传入；
  • arg：传递给 start_routine() 函数的参数。一般情况下，需要将 arg 指向一个全局或堆变量，即在线程的生命周期中，该 arg 指向的对象必须存在，否则如果线程中访问了该对象将会出现错误。当然也可将参数 arg 设置为 NULL，表示不需要传入参数给 start_routine() 函数。

返回值：成功返回 0，失败返回非 0 错误码，不像其它库函数或系统调用一样设置 errno。

子线程创建成功以后，就会加入到系统的调度队列中，获取到 CPU 使用权以后就会从指定的 start_routine() 函数开始执行。

终止线程 pthread_exit()

除了在线程函数中执行 return 语句终止线程外，终止线程的方式还有多种：

  • 线程调用 pthread_exit() 函数；
  • 调用 pthread_cancel() 取消线程。

[!warning] Warning
如果进程中的任意线程调用 exit()、_exit() 或者 _Exit()，那么将会导致整个进程终止。

pthread_exit() 是多线程编程中线程主动退出的重要机制，用于显式终止当前线程的执行，并可以选择返回一个退出状态值。函数原型如下：

  • retval：一个指向线程退出状态的指针。如果不需要传递状态，可以设为 NULL。其他线程可以通过 pthread_join() 获取这个值。

参数 retval 所指向的内容不应该分配于线程栈中，因为线程终止以后，没法确定线程栈中的内容是否有效。同一个道理，线程函数的返回值也不应该分配于线程栈中。推荐的做法是返回堆内存、全局变量或静态变量。

调用 pthread_exit() 相当于在线程函数中执行 return 语句，不同之处在于，pthread_exit() 可以出现在线程函数所调用的任意函数中。

如果主线程 main() 调用 pthread_exit()，进程会继续运行，直到所有其他线程结束，进程才会终止。而如果主线程中直接 return 或调用 exit()，整个进程会终止，包括所有线程。

回收线程 pthread_join()

在父、子进程当中，父进程可通过 wait() 或 waitpid() 阻塞等待子进程退出并获取其终止状态，回收子进程资源。

在线程当中也需要如此，通过调用 pthread_join() 函数来阻塞等待线程的终止，并获取线程的退出码，回收线程资源。pthread_join() 的函数原型为：

  • thread：要等待的线程的 pthread_t 标识符。
  • retval：用于存储线程的退出状态（pthread_exit() 或 return 的值），如果不需要可以传 NULL。

返回值：成功返回 0，失败返回非 0 错误码。

进程中的任意线程均可调用 pthread_join() 函数来等待另一个线程的终止。

一个线程只能被 join 一次，重复调用会导致 未定义行为（UB）。

pthread_join() 表示等待线程结束并回收资源，pthread_detach() 表示让线程自行释放资源，二者选择一个即可。如果都不选，那么线程终止以后就可能变成“僵尸线程”，浪费系统资源。当然，如果进程中存在着僵尸线程并未得到回收，当进程终止之后，进程会被其父进程回收，所以僵尸线程同样也会被回收。

分离线程 pthread_detach()

pthread_detach() 用于分离指定线程，分离后，系统在线程终止时能够自动回收线程资源并将其移除。

一个线程既可以将另一个线程分离，同时也可以将自己分离：pthread_detach(pthread_self());。

一旦线程处于分离状态，就不能再使用 pthread_join() 来获取其终止状态。

线程分离的过程是不可逆的，一旦处于分离状态之后便不能再恢复到之前的状态。处于分离状态的线程，当其终止后，能够自动回收线程资源。

取消线程 pthread_cancel()

有时候，在程序设计需求当中，需要向一个线程发送一个请求，要求它立刻退出，我们把这种操作称为取消线程。

pthread_cancel() 用于 请求取消（终止）另一个线程。

发出取消请求之后，函数 pthread_cancel() 立即返回，不会等待目标线程的退出。一般情况下，目标线程会立即退出，但是线程也可以设置自己不被取消或者控制如何被取消。

所以， pthread_cancel() 不会立即强制终止目标线程，而是发送一个取消请求，目标线程可以选择在合适的时机终止自己。

线程可以通过 pthread_setcancelstate() 和 pthread_setcanceltype() 来设置线程的取消状态和取消类型。

pthread_setcancelstate() 用于启用或禁用当前线程的可取消性（Cancellation），参数 state 可选：

  • PTHREAD_CANCEL_ENABLE：线程可以接收取消请求（默认）；
  • PTHREAD_CANCEL_DISABLE：线程忽略取消请求。

如果线程可取消，那么通过 pthread_setcanceltype() 可以进一步设置线程的取消类型（Cancellation Type），即线程如何响应取消请求。参数 type 可选：

  • PTHREAD_CANCEL_DEFERRED：延迟取消，即取消请求被暂时挂起，直到线程在遇到 取消点（Cancellation Point） 时才终止（默认）；
  • PTHREAD_CANCEL_ASYNCHRONOUS：异步取消，线程可能在任何指令处被终止（危险）。

那么什么是取消点呢？取消点是 POSIX 线程库中定义的一些特殊函数，在这些位置才会去检查是否有待处理的取消请求。取消点的设定是为了防止线程在关键操作中被突然终止。非取消点函数不会响应取消请求，除非手动插入 pthread_testcancel()。

POSIX 标准定义的取消点包括（部分列表）：

函数类别 示例函数
I/O 操作 read(), write(), open(), close()
线程同步 pthread_cond_wait(), pthread_join()
睡眠/延时 sleep(), nanosleep(), usleep()
文件操作 fprintf(), fscanf(), fflush()
网络操作 accept(), connect(), recv()
其他 wait(), system()

完整列表参考：man 7 pthreads

线程清理函数

使用 atexit() 函数可以注册进程终止处理函数，当进程调用 exit() 退出时就会执行进程终止处理函数。

与进程不同，一个线程可以注册多个清理函数，这些清理函数记录在栈中，每个线程都可以拥有一个清理函数栈，栈是一种先进后出的数据结构，也就是说它们的执行顺序与注册（添加）顺序相反，当执行完所有清理函数后，线程终止。

线程通过函数 pthread_cleanup_push() 和 pthread_cleanup_pop() 分别负责向调用线程的清理函数栈中添加和移除清理函数：

调用 pthread_cleanup_push() 时，需要出入清理函数指针 routine 和对应的参数 arg，这个清理函数是没有返回值的。

调用 pthread_cleanup_pop() 用于控制清理函数的执行，参数 execute 为 1 时表示执行栈顶的清理函数，为 0 时表示不执行，直接栈顶的清理函数从栈中移除。

触发清理函数执行的条件是：

  • 线程被 pthread_cancel() 取消。
  • 线程调用 pthread_exit() 终止。
  • 显式调用 pthread_cleanup_pop(1)。

除了以上三种情况之外，其它方式终止线程将不会执行线程清理函数，譬如在线程函数中执行 return 语句退出时不会执行清理函数。

pthread_cleanup_push() 和 pthread_cleanup_pop() 实际上是通过宏来实现的，这两个函数必须成对出现，它们必须位于 同一作用域，且像 { } 一样严格匹配。否则会报编译错误。
