线程同步

竞态条件：指线程/多进程编程中，程序的 正确性依赖于线程/进程的执行时序。当多个线程 无序访问共享资源，且最终结果取决于线程调度的随机性时，就会发生竞态条件。它可能导致数据不一致、程序崩溃或不可预测的行为。

竞态条件的核心原因：

  • 共享资源：多个线程同时访问同一数据（如全局变量、文件、内存等）。
  • 非原子操作：操作可能被线程调度打断。
  • 缺乏同步机制：未使用锁、信号量等保护共享资源。

[!NOTE] 概念解析

  • 原子操作是 不可分割的操作，在多线程/多进程环境中，它能确保某个操作 要么完全执行，要么完全不执行，不会被其他线程的代码打断。

  • 同步：是指 协调并发执行的线程或进程，确保它们 有序、安全地访问共享资源，避免数据竞争（Data Race）和竞态条件（Race Condition）。

一个典型的例子是：两个线程同时修改一个全局变量

这里我们启动了两个线程去对全局变量 counter 进行递增，我们预想的是，每个线程递增 10000 次，那么 counter 最终就是 20000。但是实际上，counter++; 这个操作并不是一个原子操作，它分为 3 步：

  1. 从内存读取 counter 到寄存器。
  2. 寄存器值加 1。
  3. 将结果写回内存。

两个线程并行时，可能会同时读取 counter，并各自加 1 后写回，从而导致部分递增丢失，那么 counter 的最终结果大概率是比 20000 小的。要想得到正确的结果，就必须保证执行任一时刻只能有一个线程执行 counter++; 操作。

在这个例子中，counter 的最终状态取决于两个线程执行的顺序和时机，也就是我们说的产生了竞态条件。

为了确保程序执行结果的正确性和预期一致，需要通过适当的线程同步机制来避免竞态条件。

Linux 系统提供了多种用于实现线程同步的机制，常见的方法有：互斥锁、条件变量、自旋锁以及读写锁等。

互斥锁

互斥锁（Mutex）：保证同一时刻只有一个线程可以执行临界区的代码。

互斥锁是一种同步机制，用来控制对共享资源的访问。一般情况下，每一个共享资源对应一个把互斥锁，锁的个数和线程的个数无关。

在任何时刻，最多只能有一个线程持有特定的互斥锁。如果一个线程试图获取一个已经被其他线程持有的锁，那么请求锁的线程将被阻塞，直到锁被释放。

互斥锁使用 pthread_mutex_t 联合体表示，定义在 <pthreadtypes.h> 头文件中。

pthread_mutex_lock() 会对互斥锁进行加锁。如果互斥锁处于未锁定状态，则此次调用会上锁成功，函数调用将立马返回；如果互斥锁此时已经被其它线程锁定了，那么调用 pthread_mutex_lock() 会一直阻塞，直到成功获取锁。如果线程不希望被阻塞，可以使用 pthread_mutex_trylock() 函数，它会返回返回错误码 EBUSY 而不是被阻塞。

pthread_mutex_unlock() 会将处于锁定状态的互斥锁进行解锁，并唤醒其它等待该锁的进程。

加锁和解锁必须成对出现，而且遵循谁持有锁，谁负责解锁的规则。尝试对其他线程锁定的锁进行解锁会导致错误。

使用时要注意：

  1. 每次 lock 必须对应一次 unlock，二者必须成对出现；
  2. 避免重复加锁；
  3. 临界区应该尽可能短。长时间持有锁会降低并发性能。

销毁互斥锁

pthread_mutex_destroy() 是 POSIX 线程库中用于 销毁互斥锁（Mutex） 的函数，它会释放互斥锁占用的系统资源。

一般来说，使用 pthread_mutex_init() 动态初始化的互斥锁必须手动销毁，而使用 PTHREAD_MUTEX_INITIALIZER 静态初始化的互斥锁则无需手动销毁，由系统自动管理。

需要注意的是：

  • 必须在所有线程释放锁后才能销毁；
  • 没有初始化的互斥锁也不能销毁；

销毁后的互斥锁不能再被 pthread_mutex_lock 或 pthread_mutex_unlock 使用，除非重新初始化。这也就是说，销毁后的锁可以被重新初始化。

条件变量

条件变量（Condition Variable）是用于线程间同步的另一个重要机制。

条件变量允许线程在条件不满足时休眠，当条件被其他线程改变时自动唤醒。

条件变量解决了 “忙等待”（Busy-Waiting）的低效问题，是生产者-消费者模型、线程池等场景的核心组件。

通常情况下，条件变量和互斥锁搭配使用，避免不安全的访问。

[!NOTE] 条件变量必须与互斥锁配合使用的原因

  1. 保护共享数据：检查条件和等待操作必须是原子的，防止竞态条件；

  2. 避免丢失唤醒：确保在等待之前和开始等待之间不会有其他线程改变条件并发送信号。

条件变量的初始化与销毁

条件变量使用 pthread_cond_t 数据类型来表示，同样有静态和动态两种初始化方式：

  1. 静态初始化，使用 PTHREAD_COND_INITIALIZER 宏：
  1. 动态初始化，使用 pthread_cond_init()：
  • cond ：指向 pthread_cond_t 条件变量对象；
  • attr ：指向一个 pthread_condattr_t 类型对象，用于买描述条件变量的属性，可以设为 NULL 表示使用默认值。

使用 pthread_cond_init() 函数初始化条件变量，当不再使用时，需要使用 pthread_cond_destroy() 销毁条件变量。

条件变量的使用流程

条件变量的使用流程大概如下：

  • 等待条件的线程：
    1. 获取互斥锁（pthread_mutex_lock()）。
    2. 检查条件：如果条件不满足，调用 pthread_cond_wait() 进入等待（自动释放锁）。
    3. 条件满足后： pthread_cond_wait() 返回时 已重新持有锁，继续操作共享数据。
    4. 释放锁（pthread_mutex_unlock()）。

[!warning] 必须使用 while 循环，而不是 if 语句检查条件

  • 当有多于一个线程在等待条件变量时，任何线程都有可能会率先醒来获取互斥锁，率先醒来获取到互斥锁的线程可能会对共享变量进行修改，进而改变判断条件的状态。

  • 防止虚假唤醒。

  • 修改条件的线程
    1. 获取互斥锁（pthread_mutex_lock()）。
    2. 修改共享数据（使条件成立）。
    3. 发送信号（pthread_cond_signal() 或 pthread_cond_broadcast()）。
    4. 释放锁（pthread_mutex_unlock()）。
条件变量的等待

在程序中判断某个条件不满足时，就可以调用 pthread_cond_wait() 先将线程置为阻塞状态。

  • cond：指向条件变量的指针；
  • mutex：指向与条件变量关联的互斥锁的指针；

通常情况下，条件判断以及 pthread_cond_wait() 函数调用均在互斥锁的保护下，也就是说，在此之前线程已经对互斥锁加锁了。调用 pthread_cond_wait() 函数时，调用者把互斥锁传递给函数，函数会自动把调用线程放到等待队列中，然后将互斥锁解锁；当 pthread_cond_wait() 被唤醒返回时，会再次获得互斥锁。

pthread_cond_wait() 的内部实现机制：

  1. 将调用线程加入条件变量的等待队列
  2. 原子地释放互斥锁并让线程进入等待状态
  3. 当被唤醒时，重新竞争获取互斥锁
  4. 成功获取锁后返回调用者
条件变量的通知

当条件满足时，需要向等待该条件的一个或多个线程发送通知，告诉它们某个共享变量的状态已经改变。那么，之前一直在阻塞等待条件的线程就会被唤醒，然后重新检查条件是否满足。

函数 pthread_cond_signal() 和 pthread_cond_broadcast() 均可向指定的条件变量发送通知。

二者的区别在于，pthread_cond_signal() 通常会唤醒最早等待的线程（Linux 中），而 pthread_cond_broadcast() 则是唤醒所有等待线程。前者的开销小，但只会唤醒一个线程来处理事件。

特性 pthread_cond_signal() pthread_cond_broadcast()
唤醒范围 至少一个等待线程 所有等待线程
适用场景 单资源可用通知 多资源可用或状态完全改变
线程调度 通常唤醒最早等待的线程 唤醒所有线程竞争
系统开销 较小 较大

[!info] 最佳实践

  1. 默认使用 pthread_cond_signal()，除非明确需要 pthread_cond_broadcast()；

  2. 唤醒逻辑尽量简单，避免复杂条件。

用条件变量实现生产者-消费者模型

  • 生产者：生成数据项并放入缓冲区，如果缓冲区已满则等待

  • 消费者：从缓冲区取出数据项进行处理，如果缓冲区为空则等待

  • 缓冲区：有限大小的共享存储区域，同一时刻只能有一个线程修改缓冲区数据

自旋锁

自旋锁是一种忙等待锁，当线程尝试获取已被占用的锁时，不会进入休眠状态，而是通过循环不断检查锁状态（“自旋”），直到锁可用。

而互斥锁是一种阻塞锁，当线程尝试获取已被占用的锁时，会进入休眠状态，让出 CPU 资源，直到锁被释放后被系统唤醒。

自旋锁最大的问题是，它在未获得锁的情况下，会一直处于运行状态（自旋），所以一直占用着 CPU。如果不能在很短的时间内获取锁，这无疑会使 CPU 效率降低。

自旋锁通常用于以下情况：需要保护的代码段执行时间很短，这样就会使得持有锁的线程会很快释放锁，而“自旋”等待的线程也只需等待很短的时间。

互斥锁不会一直占用 CPU，但比自旋锁多了切换线程上下文的开销。

现代 Linux 的互斥锁实际上是混合型锁，在锁被占有的情况下，它会先自旋一段时间，如果仍然没有获取锁，才会进入休眠状态，结合了自旋锁和互斥锁二者的优点。

特性 自旋锁 互斥锁
等待机制 忙等待（循环检测） 阻塞（线程休眠）
实现层级 通常用户态实现 需要内核支持
性能开销 无上下文切换，但消耗 CPU 周期 有上下文切换开销
适用场景 短临界区（通常<1ms） 长临界区
线程状态 始终保持运行状态 可能进入阻塞状态

自旋锁相关的 API 如下：

参数 lock 指向自旋锁对象，参数 pshared 表示自旋锁的进程共享属性，可以取值如下：

  • PTHREAD_PROCESS_SHARED：共享自旋锁。该自旋锁可以在多个进程中的线程之间共享；
  • PTHREAD_PROCESS_PRIVATE：私有自旋锁。只有本进程内的线程才能够使用该自旋锁。

读写锁

读写锁是一种特殊的同步机制，它允许多个线程同时进行读操作，但只允许一个线程进行写操作。

也就是说：

  1. 当读写锁处于写加锁状态时，在这个锁被解锁之前，所有试图对这个锁进行加锁操作（不管是以读模式加锁还是以写模式加锁）的线程都会被阻塞。
  2. 当读写锁处于读加锁状态时，所有试图以读模式对它进行加锁的线程都可以加锁成功；但是任何以写模式对它进行加锁的线程都会被阻塞，直到所有持有读模式锁的线程释放它们的锁为止。

这种读写锁在读多写少的场景下能显著提高并发性能，比如查询数据库。

读写锁的初始化与销毁

读写锁使用 pthread_rwlock_t 数据类型表示。与互斥锁、自旋锁类似，在使用读写锁之前也必须对读写锁进行初始化操作。

动态初始化时，可以通过参数 attr 设置读写锁的属性。

读写锁的加锁与解锁
  • rdlock：获取读锁，若有写锁则阻塞。
  • wrlock：获取写锁，若有读锁或写锁则阻塞。
  • unlock：释放锁。

线程池

线程池（Thread Pool）是一种多线程处理形式，用于管理一组预先创建的线程来执行任务。

线程池是一个包含多个工作线程的集合，这些线程在程序启动时创建并保持空闲状态，等待任务分配。当有新任务到来时，线程池从空闲线程中分配一个线程来执行任务，任务完成后，线程返回池中等待下一次任务，而不是被销毁。

线程池的主要组成部分：

  1. 线程集合：一组预先创建的工作线程，通常数量固定。
  2. 任务队列：存储待执行任务的队列。
  3. 管理机制：负责任务分配、线程调度和资源管理。
  4. 同步原语：用于协调线程访问共享资源。
