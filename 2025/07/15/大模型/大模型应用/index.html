大模型架构

整体架构解释

该架构采用分层设计，从底层基础设施到顶层应用形成完整生态：

  1. 基础设施层 提供计算、存储和网络资源；
  2. 云原生层 实现容器化和自动化部署；
  3. 模型层 为核心能力层，包含预训练模型和部署工具；
  4. 应用技术层 整合关键技术（如 RAG、Agent），提升模型实用性；
  5. 平台层 提供工具链，降低开发门槛；
  6. 应用层 面向具体场景，交付最终产品。

这种模块化设计支持灵活扩展，适用于不同规模和领域的 AI 应用开发。

1. 基础设施层

  • GPU/TPU/昇腾 ：高性能计算硬件，加速AI模型训练和推理（如NVIDIA GPU、Google TPU、华为昇腾芯片）。
  • CPU ：通用处理器，负责基础计算任务。
  • RAM ：内存，临时存储数据以提高访问速度。
  • HDD ：硬盘存储，长期保存数据。
  • Network ：网络通信，连接各组件并传输数据。

2. 云原生层

  • Docker ：容器化工具，封装应用及其依赖，实现标准化部署。
  • K8S (Kubernetes) ：容器编排平台，管理容器集群的调度、扩展和负载均衡。

3. 模型层

  • 对话模型 ：

    • ChatGPT ：OpenAI开发的超大规模语言模型，擅长对话理解和生成。
    • Deepseek ：开源对话模型，支持多语言交互。

  • 嵌入模型 ：

    • nomic-embed-text ：文本嵌入模型，将文本转化为向量表示。
    • BGE ：百度文心一言系列的嵌入模型，用于语义相似度计算。

  • 语音模型 ：

    • Whisper ：OpenAI的语音识别模型，支持多语言转录。
    • Bark ：语音合成模型，可生成自然的人声。

  • 图像模型 ：

    • Stable Diffusion ：开源图像生成模型，根据文本描述生成图片。
    • DALL·E 2 ：OpenAI的图像生成模型，支持复杂场景创作。

  • 代码模型 ：

    • Copilot ：GitHub的代码生成工具，基于Codex模型。
    • CodeGeeX ：微软的代码助手，支持多种编程语言。

  • LLM 部署工具 ：

    • Ollama ：轻量级模型部署框架，简化本地运行大模型。
    • VLLM ：高效推理引擎，优化大模型的批量推理性能。

4. 应用技术层

  • Agent智能体 ：自主决策的AI代理，通过交互完成复杂任务（如AutoGen）。
  • COT思维链 ：Chain of Thought（思维链）技术，让模型逐步推理解决问题。
  • NL2SQL ：自然语言到SQL转换工具，将用户指令转为数据库查询语句。
  • 向量数据库 ：存储和检索高维向量（如Qdrant、Milvus），用于语义搜索。
  • RAG检索增强生成 ：结合检索（R）和生成（G）技术，提升回答准确性。
  • Workflow任务编排 ：自动化流程管理工具（如LangChain Agents）。
  • Fine-tuning微调 ：针对特定任务微调预训练模型，提升领域适配性。
  • Prompt提示词工程 ：优化输入提示的设计，引导模型输出符合预期的结果。

5. 平台层

  • 通用应用开发 ：

    • Coze ：低代码开发平台，快速构建AI应用。
    • Dify ：对话式AI开发框架，支持多模态交互。

  • RAG构建 ：

    • RAG Flow ：端到端RAG系统搭建工具。
    • LlamaIndex ：构建知识库索引和检索的库。

  • 工作流编排 ：

    • LangChain ：构建复杂AI工作流的框架。
    • n8n ：可视化工作流自动化工具。

  • 数据/数据库问答 ：

    • DB-GPT ：数据库问答模型，直接解析数据库内容。
    • Chat2Query ：将自然语言转为数据库查询的工具。

  • Agent开发 ：

    • AutoGPT ：自主规划任务的AI代理。
    • AutoGen ：Meta开发的多Agent协作框架。

6. 应用层

  • 生产力工具 ：

    • 文档生成 ：自动生成报告、邮件等文本。
    • 代码辅助 ：实时代码补全和调试建议。

  • 知识管理与检索 ：

    • 企业知识库 ：构建私有知识库并支持语义搜索。
    • 高精度问答 ：基于知识库的精准答案提取。

  • 复杂任务执行 ：

    • 智能工作流 ：自动化跨系统的业务流程。
    • 智能助手 ：多模态交互的虚拟助手（如客服机器人）。

  • 数据分析与决策 ：

    • 自然语言查询数DB ：通过口语化指令分析数据库。
    • 市场报告解读 ：自动解析和总结行业报告。

  • 垂直行业解决方案 ：

    • AI辅助诊断 ：医疗影像分析和疾病预测。
    • 智能家教 ：个性化教育辅导系统。

安装 ollama 并下载对应模型

ollama 是什么

Ollama 是一个 本地化大语言模型（LLM）运行框架，允许用户在个人电脑上轻松下载、运行和管理开源大模型（如 LLaMA、Mistral、DeepSeek 等），无需依赖云端服务。

功能 说明
本地运行模型 直接在电脑上运行 LLM，完全离线，保护隐私。
一键下载模型 通过 ollama pull 命令下载模型（如 llama3、deepseek-coder）。
简化部署 自动处理依赖（如 GPU 加速、量化），无需手动配置复杂环境。
多平台支持 支持 Windows、macOS、Linux（包括 ARM 设备如 Raspberry Pi）。
REST API 支持 提供本地 API，方便与其他工具（如 Open WebUI、LangChain）集成

如何修改 Ollama 默认的模型安装路径？

Ollama 默认会将模型下载到 C 盘用户目录下的 .ollama 文件夹（如 C:\Users\imp\.ollama）。

可以通过通过环境变量 OLLAMA_MODELS 修改模型路径：

  1. 打开系统环境变量设置
  2. 新建用户变量：
    • 在 "用户变量"部分，点击 “新建”。
    • 输入以下内容：
      • 变量名：OLLAMA_MODELS
      • 变量值：D:\ollama_models（或其他你想要的路径）
  3. 点击 “确定” 保存设置。
  4. 关闭所有终端/Ollama 相关程序，并重新启动 Ollama 服务（或重启电脑）。

配置 MCP 服务

什么是 MCP 服务？

官方主页： https://modelcontextprotocol.io/introduction

MCP 全称是 Model Context Protocol，即模型上下文协议，由 Claude 的母公司 Anthropic 于 24 年底开源发布。简单来说，MCP 就是 AI 大模型的标准化工具箱，大模型可以利用这些工具与外部互动，获取信息并完成具体的任务。

MCP 服务作为 AI 与外部工具的中间层，代替人类访问并且操作外部工具（比如浏览器、文件系统、数据库等），每个 MCP Server 都专精一类工作，有的负责和读写浏览器，有的负责读取本地文件等。

MCP Server 通常是运行在本地的 nodejs 或者 python 程序，大模型通过操作系统的标准输入输出通道（stdio）来以规定的消息格式来调用它，MCP Server 接到这些请求后，通过自身功能或者访问外部 API 来完成具体的任务。

MCP 的最大优点在于整合了之前各家大模型不同的标准，市面上几乎所有的大模型都可以接入 MCP。

搭建 RAGFlow 知识库

RAGFlow 是什么？

RAGFlow 是一款基于深度文档理解构建的开源 RAG（Retrieval-Augmented Generation，检索增强生成）引擎。RAGFlow 可以为各种规模的企业及个人提供一套精简的 RAG 工作流程，结合大语言模型（LLM）针对用户各类不同的复杂格式数据提供可靠的问答以及有理有据的引用。

Ragflow 仓库： https://github.com/infiniflow/ragflow

RAGFlow 主页： https://ragflow.io/

为什么要使用 RAG 技术？RAG 和模型微调的区别？

  • 大模型的幻觉问题是指模型生成与输入无关、不符合事实或逻辑上不合理的内容。
  • 微调技术和 RAG 技术：
    • 微调：在已有的预训练模型基础上，再结合特定任务的数据集进一步对其进行训练，使得模型在这一领域中表现更好；
    • RAG：在生成回答之前，通过信息检索从外部知识库中查找与问题相关的知识，增强生成过程中的信息来源，从而提升生成的质量和准确性。
    • 共同点：都是为了赋予模型某个领域的特定知识，解决大模型的幻觉问题。
  • RAG （Retrieval-Augmented Generation）的原理:
    • 检索（Retrieval）：当用户提出问题时，系统会从外部的知识库中检索出与用户输入相关的内容。
    • 增强（Augmentation）：系统将检索到的信息与用户的输入结合，扩展模型的上下文。然后再传给生成模型（也就是 Deepseek）；
    • 生成（Generation）：生成模型基于增强后的输入生成最终的回答。由于这一回答参考了外部知识库中的内容，因此更加准确可读。

大模型可以简单的分为Chat模型和Embedding模型。

检索的过程需要使用 Embedding（嵌入）模型对知识库文件进行解析，Embedding 的主要作用就是将自然语言转化为机器可以理解的高维向量。

RAGFlow配置时需要同时配置这两种模型。嵌入模型也可以用Ollama在本地运行。

修改Ollama环境变量

因为RAGFlow是运行在Windows的虚拟机WSL里面的。默认情况下，OLLAMA绑定在本地回环地址127.0.0.1:11434，为了让虚拟机里面的RAGFlow正常访问，需要将Ollama的监听地址设置为0.0.0.0:11434，11434是Ollama的默认端口。可以通过通过环境变量 OLLAMA_MODELS 修改Ollama的监听地址 ：

  1. 打开系统环境变量设置
  2. 新建用户变量：
    • 在 "用户变量"部分，点击 “新建”。
    • 输入以下内容：
      • 变量名：OLLAMA_HOST
      • 变量值：0.0.0.0:11434（或其他你想要的路径）
  3. 点击 “确定” 保存设置。
  4. 关闭所有终端/Ollama 相关程序，并重新启动 Ollama 服务（或重启电脑）。

vLLM

vLLM和Ollama的区别？

vLLM 和 Ollama 是两种流行的大型语言模型（LLM）部署工具，各自适用于不同的场景。

指标 Ollama vLLM
推理速度 较慢（适合本地小规模使用） 极快（支持连续批处理、多 GPU 并行）
内存占用 较低（适合消费级硬件） 较高（优化显存管理，但仍需高端 GPU）
并发能力 有限（单机部署，并发请求性能较弱） 高（支持分布式推理，适合大规模服务）
易用性 安装简单，开箱即用 配置较为复杂，适合有技术背景的团队
成本 低 高
使用场景 个人开发者、小型项目、离线应用（如本地文档分析、个人助手） 企业级 AI 服务（如智能客服、搜索引擎），需要高吞吐量、低延迟推理的场景

创建应用

Dify 上可以创建多种不同的应用类型，分别是聊天助手、文本生成应用、Agent 、chatflow、工作流。

你可以通过 3 种方式在 Dify 的工作室内创建应用：

  • 基于应用模板创建（新手推荐）：选择 「工作室 」，在应用列表内选择 「从模板创建」。

  • 创建一个空白应用：选择 「工作室」 ，在应用列表内选择 「从空白创建 」。

  • 通过 DSL 文件（本地/在线）创建应用：Dify DSL 是由 Dify.AI 所定义的 AI 应用工程文件标准，文件格式为 YML。该标准涵盖应用在 Dify 内的基本描述、模型参数、编排配置等信息。支持本地导入或 URL 导入。

工作流

开源的工作流合集： https://github.com/svcvit/Awesome-Dify-Workflow ，可以通过 DSL 文件导入。

  • 节点：节点是工作流的关键构成，通过连接不同功能的节点，执行工作流的一系列操作。
  • 变量：变量用于串联工作流内前后节点的输入与输出，实现流程中的复杂处理逻辑，包含系统变量、环境变量和会话变量。

变量

大部分节点设有输入和输出项，但每个节点的输入信息不一致，各个节点所输出的答复也不尽相同。

变量作为一种动态数据容器，能够存储和传递不固定的内容，在不同的节点内被相互引用，实现信息在节点间的灵活通信。

系统变量是工作流应用内预设的系统级参数，可以被其它节点全局读取。系统级变量均以 sys 开头。Workflow 类型应用提供以下系统变量：

变量名称 数据类型 说明 备注
sys.files Array[File] 文件参数，存储用户初始使用应用时上传的图片 图片上传功能需在应用编辑页面右上角的“功能”处开启
sys.user_id String 用户 ID，每个用户在使用工作流应用时，系统会自动向用户分配唯一标识符，用以区分不同的对话用户
sys.app_id String 应用 ID，系统会向每个 Workflow 应用分配一个唯一的标识符，用以区分不同的应用，并通过此参数记录当前应用的基本信息 面向具备开发能力的用户，通过此参数区分并定位不同的 Workflow 应用
sys.workflow_id String Workflow ID，用于记录当前 Workflow 应用内所包含的所有节点信息 面向具备开发能力的用户，可以通过此参数追踪并记录 Workflow 内的包含节点信息
sys.workflow_run_id String Workflow 应用运行 ID，用于记录 Workflow 应用中的运行情况 面向具备开发能力的用户，可以通过此参数追踪应用的历次运行情况

环境变量用于保护工作流内所涉及的敏感信息，例如运行工作流时所涉及的 API 密钥、数据库密码等。它们被存储在工作流程中，而不是代码中，以便在不同环境中共享。
支持以下三种数据类型：String 字符串、Number 数字、Secret 密钥。

环境变量拥有以下特性：

  • 环境变量可在大部分节点内全局引用；
  • 环境变量命名不可重复；
  • 环境变量为只读变量，不可写入。

工作流不涉及会话变量。

节点

节点是工作流中的关键构成，通过连接不同功能的节点，执行工作流的一系列操作。

dify 中的核心节点包括：

  • 开始（Start）
  • 结束（End）
  • 回复（Answer）
  • 大语言模型（LLM）
  • 知识检索（Knowledge Retrieval）
  • 问题分类（Question Classifier）
  • 条件分支（IF/ELSE）
  • 代码执行（Code）
  • 模板转换（Template）
  • 变量聚合（Variable Aggregator）
  • 参数提取器（Parameter Extractor）
  • 迭代（Iteration）
  • HTTP 请求（HTTP Request）
  • 工具（Tools）
  • 变量赋值（Variable Assigner）
  • 循环（Loop）
