Qt中的事件处理

发表于2024-01-11|更新于2024-01-11|Qt
|总字数:1.3k|阅读时长:4分钟|浏览量:

事件系统

QWidget 类是所有界面组件类的基类，QWidget 类定义了大量与事件处理相关的数据类型和接口函数。

事件的产生与派发

事件的产生

事件表示应用程序中发生的操作或者变化，比如移动鼠标、点击、按键等。在 Qt 中，事件是 QEvent 类及其派生类的实例对象，比如 QKeyEvent 是按键事件类，QMouseEvent 是鼠标事件类。

按照事件的来源，事件可以分为三类：

  1. 自生事件：由窗口系统产生。比如 QKeyEvent、QMouseEvent 等。自生事件会进入系统队列，然后被应用程序的事件循环逐个处理。
  2. 发布事件：由 Qt 或应用程序产生的事件。比如定时器定时产生的 QTimerEvent 事件，程序调用静态函数 postEvent() 产生的事件。发布事件会进入 Qt 事件队列，然后由应用程序的事件循环进行处理。
  3. 发送事件：由 Qt 或应用程序定向发送给某个对象的事件。应用程序调用静态函数 sendEvent() 产生发送事件，由对象的 event() 函数直接处理。

postEvent() 函数发布事件后会直接退出，也就是说发布事件的处理是异步的，而sendEvent() 函数发送事件需要等待对象处理完事件以后才退出，也就是说发送事件的处理时同步的。

事件的派发

pyqt 应用程序的 main 文件一般是这样的：

app.exec() 运行之后开始应用程序的事件循环，它的功能就是不断地检查系统队列和 Qt 事件队列中有没有未处理的自生事件和发布事件，然后派发给对象去处理。

注意，应用程序的事件循环只处理自生事件和发布事件，而不会处理发送事件，因为发送事件由应用程序直接派发给某个对象，是以同步的方式处理的。

为了避免事件队列不能及时处理而导致界面卡顿，一般会在涉及到大量计算和数据传输的程序中使用多线程，将界面更新和数据处理分别用两个线程处理，就不会出现界面无响应的情况。

另一种简单的处理方法是在需要长时间占用 CPU 的代码段中调用 QCoreApplication 的静态函数 processEvents() 将事件队列中没有及时处理的事件派发出去。

事件类与事件类型

QEvent 是 Qt 框架中用于表示事件的基本类。应用程序可以使用 QEvent 来处理用户交互、更新 UI 和响应系统事件。QEvent 类提供了以下成员函数：

  • type (): 返回事件的类型。事件类型由 QEvent::Type 枚举定义。
  • isAccepted(): 检查事件是否已被接受。 如果事件已被接受，则返回 true；否则返回 false。
  • accept(): 接受事件。 这意味着应用程序将处理事件。
  • ignore(): 忽略事件。 这意味着应用程序将不处理事件。
  • sender(): 返回发送事件的对象。
  • receiver (): 返回接收事件的对象。

每个事件都有唯一的事件类型，也有对应的事件类，但是有的事件类可以处理多种类型的事件。例如， QMouseEvent 是鼠标事件类，用它创建的事件的类型可以是鼠标双击事件 QEvent::MouseButtonDblClick 或鼠标移动事件 QEvent::MouseMove 等。

事件的处理

任何从 QObject 派生的类都可以处理事件，通过重写 event() 函数就可以在接收到事件时继续处理。

event() 的函数原型为：bool QObject: : event(QEvent *e)，通过 e->type() 就可以判断事件的类型进行相应的处理。

在重写的 event() 函数里，需要用过函数 accept() 或 ignore() 来确定是否接受或忽略事件。被接受的事件由接受者处理，被忽略的事件则传播到父容器组件的 event() 函数处理，这一过程称为事件的传播。

QWidget 类是所有界面组件类的基类，它重新实现了函数 event()，并针对一些典型类型的事件定义了专门的事件处理函数，函数 event() 会根据事件类型自动去运行相应的事件处理函数。例如，如果事件类型是 QEvent::MouseMove, 对应的事件处理函数是 mouseMoveEvent ()；如果事件类型是 QEvent::Paint, 对应的事件处理函数是 paintEvent()。QWidget 中定义的典型事件处理函数不能被外部调用，但可以被派生类重新实现。

如果从 QWidget 或其派生类继承自定义了一个类需要对表中的某种类型的事件进行处理，那么只需重新实现表中与事件类型对应的事件处理函数。如果需要处理的事件在 QWidget 中没有定义事件处理函数，就需要重新实现函数 event()，判断事件类型后调用自己定义的事件处理函数。
